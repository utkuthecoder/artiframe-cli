Documentation ArtiFrame

Un framework pour des projets PHP natifs évolutifs, gérés avec zéro dépendance externe, des règles strictes et un puissant CLI. Sans dépendance, libéré de la soupe de paquets composer, un écosystème léger et rapide qui vous permet de vous concentrer sur votre logique métier.

Introduction & Philosophie

ArtiFrame est basé sur le principe "Convention over Configuration" (La convention plutôt que la configuration). La puissance d'un framework ne vient pas de la richesse des outils qu'il propose, mais de la cohérence de l'ordre qu'il établit.

Zéro Surcharge

Zéro dépendance vis-à-vis des paquets ou bibliothèques tiers de Composer. Composer est uniquement utilisé pour exécuter le mécanisme de chargement automatique des classes PSR-4 du projet. Chaque ligne de code vous appartient ; sans couches d'abstraction inutiles.

La Sécurité D'abord

La protection XSS, la validation CSRF, la désinfection contre les injections SQL et le contrôle des méthodes HTTP sont intégrés par défaut. La sécurité n'est pas une option, c'est une norme.

Ensemble de Règles Strict

Un développeur junior rejoignant le projet comprend l'architecture data-js et la structure des répertoires en quelques minutes. La cohésion de l'équipe est garantie au niveau du framework.

Priorité au CLI

Pas de création manuelle de fichiers de vue, d'API ou de classe. Le CLI génère à partir de fichiers stub, établit des liens vers les ressources et maintient la cohérence du projet.

ℹ️ Licence AGPLv3 : ArtiFrame est open source. Les œuvres dérivées que vous produisez peuvent être utilisées librement, à condition que le code source reste ouvert. La mention de droit d'auteur ne peut être supprimée.

Installation

Le CLI ArtiFrame est installé comme un outil PHP global. Il est installé une fois et utilisé dans chaque projet.

1. Installer l'Outil CLI Globalement

# Installation globale via NPM
npm install -g @artilingo/artiframe-cli

# Vérifier l'installation
artiframe

2. Shell Interactif

Tapez simplement artiframe dans le terminal et appuyez sur Entrée. Le CLI ne se ferme pas ; un shell interactif s'ouvre, écoutant continuellement les commandes :

==================================================
        ArtiFrame CLI Interactive Shell v1.0.0
==================================================
Type 'help' for commands, or 'exit' to quit.

artiframe>

3. Démarrer un Nouveau Projet

artiframe> new mon-projet

Cette commande crée le répertoire mon-projet/ et y copie toute la structure squelette : app/, bin/, config/, public/, src/, .env.example et la première page index.php.

4. Paramètres d'Environnement

cp .env.example .env

Ouvrez votre fichier .env et remplissez les informations de la base de données et de l'application. Ce fichier n'est jamais soumis au contrôle de version.

⚠️ Paramètre du Serveur Web : Pointez la racine du document (document root) d'Apache/Nginx vers le dossier /public/. Les autres répertoires ne doivent jamais être exposés à l'extérieur.

Structure des Répertoires

L'architecture créée lors du lancement du projet ; elle assure une séparation claire des responsabilités (SoC).

nom-du-projet/ ├── app/ # Couche d'infrastructure │ ├── ViewControl.php # Bootstrapper de vue (page HTML) │ ├── ApiControl.php # Bootstrapper de point de terminaison API │ ├── Database.php # Connexion de base de données basée sur PDO │ ├── DotEnv.php # Lecteur .env │ └── R2Manager.php # Gestionnaire de fichiers Cloudflare R2 │ ├── bin/ # ⚠️ Système de base — ne pas modifier directement │ ├── SystemMethod.php # Aides globales API/Backend │ ├── ViewMethod.php # Aides globales View/Frontend │ └── stubs/ # Fichiers modèles utilisés par le CLI │ ├── view.stub │ ├── api-standart.stub │ ├── api-switch-case.stub │ └── class.stub │ ├── config/ # Fichiers de configuration │ └── app-version.php # Constantes APP_VERSION et APP_ENV │ ├── public/ # ← Le seul répertoire ouvert du serveur web │ ├── assets/ │ │ ├── css/ # Fichiers CSS spécifiques à la vue │ │ └── js/ # Fichiers JS spécifiques à la vue │ ├── includes/ # Composants partagés │ │ ├── head.php │ │ ├── header.php │ │ └── footer.php │ ├── api/ # Fichiers de point de terminaison API │ └── index.php # Page d'accueil │ ├── src/ # Logique métier et classes ├── .env # Variables d'environnement (ne va pas dans git) ├── .env.example # Modèle — va dans git └── kilavuz.html # Ce document
🚫 Ne touchez pas au répertoire bin/ : Les fichiers dans bin/ sont le cœur du framework. La logique métier spécifique au projet n'est pas ajoutée ici. Les classes et services que vous ajouterez sont situés sous src/, et les composants d'infrastructure sous app/.

Architecture du Bootstrapper Critique

ArtiFrame utilise deux bootstrappers complètement indépendants. Cette architecture empêche fondamentalement les problèmes d'en-tête HTML et les failles de sécurité.

View ViewControl.php

Utilisé pour les pages HTML (fichiers de vue). Démarre la session, charge ViewMethod.

// public/profil.php — TOUT EN HAUT, avant de générer le HTML
<?php
require_once $_SERVER['DOCUMENT_ROOT']
    . '/../app/ViewControl.php';
use Bin\ViewMethod;
?>
<!DOCTYPE html>
...

API ApiControl.php

Utilisé pour les fichiers de point de terminaison API. Définit l'en-tête JSON, effectue le contrôle de la méthode HTTP, charge SystemMethod.

// public/api/utilisateur/obtenir.php
<?php
// $allowedMethods DOIT être défini avant le require
$allowedMethods = ['GET'];

require_once $_SERVER['DOCUMENT_ROOT']
    . '/../app/ApiControl.php';

use Bin\SystemMethod;
🚫 ViewControl et ApiControl ne sont jamais mélangés : Si ViewControl est requis dans un fichier API, il peut renvoyer un en-tête HTML au lieu d'un en-tête JSON et l'ensemble de la réponse API sera corrompu. Si ApiControl est requis dans une page HTML, la session ne démarre pas et la page se casse.

Ensemble de Règles Standard

Règle 1 : Architecture data-js Critique

Les événements JavaScript ne peuvent jamais être écoutés via une class ou un id. Ce sont des identités visuelles / stylistiques. Toutes les interactions JS sont gérées par l'attribut data-js. Lorsque CSS supprime une classe, le JavaScript ne plante jamais.

<!-- ❌ Anti-Pattern — non pris en charge -->
<button id="submitBtn" class="btn">Envoyer</button>
// JS: document.getElementById('submitBtn').addEventListener(...)

<!-- ✅ Norme ArtiFrame -->
<button class="btn btn-primary" data-js="login-submit">Envoyer</button>
// JS: document.querySelector('[data-js="login-submit"]').addEventListener(...)

Règle 2 : Architecture du Thème

Le mode Sombre/Clair et les thèmes sont gérés via les attributs data-theme et data-mode de la balise <html>. Les classes de corps (body classes) ne sont pas utilisées.

<!-- balise d'ouverture HTML provenant du modèle view.stub -->
<html lang="fr" data-theme="default" data-mode="light">

/* Définition du thème dans app.css */
html[data-theme="default"][data-mode="dark"] {
    --bg-color: #0b0c0e;
    --text-main: #ffffff;
}
html[data-theme="default"][data-mode="light"] {
    --bg-color: #ffffff;
    --text-main: #111111;
}

Règle 3 : Flux de Données Sécurisé

Toutes les données provenant de la base de données sont enveloppées avec display() avant d'être affichées dans le DOM. Toutes les données arrivant à l'API sont nettoyées avec sanitizeString() ou sanitizeInt() avant d'être traitées.

Règle 4 : Gestion des Erreurs avec APP_ENV

La valeur APP_ENV dans le fichier .env détermine la visibilité des erreurs. En production, le message d'erreur n'est pas affiché à l'utilisateur.

// config/app-version.php
define('APP_ENV', (int)$_ENV['APP_ENV']); // 1=Debug, 0=Production

if (APP_ENV === 1) {
    ini_set('display_errors', 1);
    error_reporting(E_ALL);
} else {
    ini_set('display_errors', 0);
}

Écosystème CLI

Le CLI ArtiFrame ouvre un shell interactif lorsque l'on tape artiframe dans le terminal. Toutes les commandes s'exécutent dans ce shell. Les commandes peuvent également être exécutées en mode unique (one-shot).

# Mode interactif (recommandé)
artiframe
artiframe> make:view admin/utilisateurs.php

# Mode unique
artiframe make:view admin/utilisateurs.php

new Commande CLI

Crée un nouveau projet ArtiFrame. Génère l'ensemble du squelette de répertoire, les fichiers bootstrapper et la première page d'index.

artiframe> new nom-du-projet

Structure créée :

nom-du-projet/ ├── app/ (ViewControl.php, ApiControl.php, Database.php, DotEnv.php) ├── bin/ (SystemMethod.php, ViewMethod.php, stubs/) ├── config/ (app-version.php) ├── public/ (index.php, assets/, includes/, api/) ├── src/ ├── .env.example └── kilavuz.html

make:view Commande CLI

Crée un nouveau fichier de page (view) et ses ressources CSS/JS spécifiques. Les ressources sont automatiquement liées à la page et le vidage du cache (cache-busting) est appliqué avec ?v=APP_VERSION.

artiframe> make:view admin/utilisateurs.php

Fichiers créés :

✔  public/admin/utilisateurs.php
✔  public/assets/css/admin/utilisateurs.css
✔  public/assets/js/admin/utilisateurs.js

Le fichier de vue créé contient le require de ViewControl au début, les inclusions head/header/footer ajoutées, et les liens CSS/JS attachés avec le cache-busting.

make:api Commande CLI

Crée un fichier de point de terminaison API en choisissant l'un des deux modèles différents. La variable $allowedMethods et le require de ApiControl.php sont prêts dans chaque nouveau fichier API.

standart — API à Action Unique

Pour les points de terminaison qui effectuent une seule tâche (connexion, envoi, suppression). La logique métier est écrite directement.

artiframe> make:api standart api/auth/connexion.php
<?php
$allowedMethods = ['POST']; // Accepter uniquement POST
require_once $_SERVER['DOCUMENT_ROOT'] . '/../app/ApiControl.php';

use Bin\SystemMethod;

// Logique métier ici...
jsonResponse(['status' => 'success'], 200);

switch-case — API Multi-Actions

Une structure qui gère les opérations CRUD pour un module dans un seul point de terminaison. L'opération à effectuer est déterminée par le paramètre action.

artiframe> make:api switch-case api/utilisateur/gerer.php
<?php
$allowedMethods = ['POST'];
require_once $_SERVER['DOCUMENT_ROOT'] . '/../app/ApiControl.php';

use Bin\SystemMethod;

$action = sanitizeString($_POST['action'] ?? '');

switch ($action) {
    case 'create':
        jsonResponse(['status' => 'success', 'message' => 'Créé.'], 200);
        break;
    case 'update':
        jsonResponse(['status' => 'success', 'message' => 'Mis à jour.'], 200);
        break;
    case 'delete':
        jsonResponse(['status' => 'success', 'message' => 'Supprimé.'], 200);
        break;
    default:
        jsonResponse(['status' => 'error', 'message' => 'Action invalide.'], 400);
}

make:class Commande CLI

Crée un nouveau fichier de classe PHP avec un espace de noms et un boilerplate de classe prêts à l'emploi. L'espace de noms est déterminé automatiquement en fonction du chemin de la classe. Si un répertoire autre que app/ et src/ (par exemple private/) est utilisé, l'outil CLI exécute automatiquement le script composer dump-autoload en arrière-plan.

artiframe> make:class src/Service/EmailService.php

Si le répertoire de la classe n'est pas spécifié, la commande renvoie une erreur :

artiframe> make:class
❌ Erreur : Le répertoire où la classe sera créée doit être spécifié ! (ex: /app ou /src)
Example: /src/Service/PaymentService

View Helpers — display() ViewMethod

Applique une protection XSS obligatoire lors de l'affichage de données provenant de la base de données ou d'entrées utilisateur dans le DOM. Renvoie une valeur par défaut au lieu de générer une erreur pour les valeurs nulles ou vides.

string display(mixed $data, string $default = '')
💡 Astuce : Utilisation de $default
Le deuxième paramètre ($default) est un texte de secours qui sera affiché lorsque les données de la base de données sont vides (null, false, chaîne vide). Par exemple, si vous utilisez display($nom, 'Sans nom') pour un utilisateur dont les données de nom ne sont pas saisies, votre page offrira un contenu significatif au lieu d'espaces vides inesthétiques. 
<!-- ❌ Non sécurisé — Crée une vulnérabilité XSS -->
<h1><?= $utilisateur['nom'] ?></h1>

<!-- ✅ Utilisation sécurisée d'ArtiFrame -->
<h1><?= display($utilisateur['nom'], 'Utilisateur Anonyme') ?></h1>

View Helpers — escapeUrl() ViewMethod

Utilisé lors de l'insertion de liens reçus des utilisateurs (par exemple, des sites web de profil) dans <a href="..."> ou <img src="...">. Rend inoffensives les charges utiles (payloads) dangereuses telles que javascript:alert(1) (Stored XSS), empêchant l'exécution de code via le lien.

string escapeUrl(string $url) 
<!-- ❌ Non sécurisé — Le code JS peut être infiltré via l'URL -->
<a href="<?= $utilisateur['website'] ?>">Visiter le site</a>

<!-- ✅ Utilisation sécurisée d'ArtiFrame -->
<a href="<?= escapeUrl($utilisateur['website']) ?>">Visiter le site</a>

View Helpers — csrfField() ViewMethod

Ajoute un champ de jeton (token) masqué aux formulaires HTML pour se protéger contre les attaques CSRF. Son utilisation est obligatoire sur chaque page contenant un formulaire POST.

string csrfField() 
<form action="/api/enregistrer.php" method="POST">
    <?= csrfField() ?>   <!-- Obligatoire pour la sécurité -->
    <input type="text" name="nom">
    <button type="submit" data-js="enregistrer-btn">Enregistrer</button>
</form>

View Helpers — Fonctions de date ViewMethod

Traite les chaînes de date au format Y-m-d H:i:s de la base de données ou les valeurs timestamp UNIX. Toutes les sorties textuelles sont localisées en fonction de la langue (tr, en, de, fr, es).

FonctionExemple de sortieDescription

month($date)07Le mois uniquement (chiffre)

formatDate($date, $format)24.07.2026 14:30Format personnalisé

💡 Comprendre les paramètres : $format et $lang
  • $format (Format) : Utilisé uniquement avec la fonction formatDate(). Accepte les lettres de format de date standard de PHP. (Par exemple : 'd/m/Y' ➔ 24/07/2026, ou 'H:i' ➔ 15:30). Vous permet de créer votre propre modèle de date lorsque les fonctions prêtes à l'emploi (day, year, etc.) sont insuffisantes.
  • $lang (Langue) : Utilisé dans les fonctions qui incluent du texte dans leur sortie (nom du mois, mot "il y a"). Si vous laissez ce paramètre vide, le système fonctionnera avec 'tr' (Turc) par défaut. Si vous créez un projet multilingue, il suffit d'entrer le code de langue (tr, en, de, fr, es) comme deuxième paramètre. (Ex : timeAgo($date, 'fr') ➔ il y a 5 minutes)

<!-- Sortie : 24 Juillet 2026 -->

<!-- Affichage de l'heure style réseau social -->

<!-- Sortie : 5 minutes ago -->

<span><?= timeAgo($date, 'de') ?></span>
<!-- Sortie : vor 5 Minuten -->

System Helpers — apiResponse() SystemMethod

C'est le générateur de sortie JSON standard et universel d'ArtiFrame. Doit être utilisé lors de l'envoi de données depuis les API vers JavaScript. Normalise le processus de développement en envoyant toujours un objet cohérent (status, message, data) au développeur JS (Frontend).

void apiResponse(string $status, string $message, array $data = [], \Throwable $exception = null)
💡 Gestion intelligente des erreurs (Prise en charge APP_ENV)
Si vous envoyez une $e (Exception) au 4ème paramètre ; en mode APP_ENV = 1 (Debug), au lieu du message écrit par l'utilisateur, l'erreur PHP réelle, la ligne et le chemin du fichier sont affichés. Cependant, lorsque le serveur est mis en mode APP_ENV = 0 (Prod), le système masque automatiquement les journaux d'Exception et ne renvoie que le message propre "Une erreur s'est produite" que vous avez écrit. 
// Réponse réussie
apiResponse('success', 'Utilisateur enregistré.', ['id' => $newId]);

// Gestion intelligente des erreurs avec Try-Catch
try {
    // Opérations de base de données...
} catch (\Exception $e) {
    // En mode Prod : "Un problème est survenu lors de l'enregistrement."
    // En mode Debug : "SQL Error: duplicate key... (Fichier: user.php Ligne: 45)"
    apiResponse('error', 'Un problème est survenu lors de l'enregistrement.', [], $e);
}

System Helpers — jsonResponse() SystemMethod

Définit l'en-tête JSON, donne le code d'état HTTP et imprime la sortie avec json_encode. (Généralement non utilisé directement, apiResponse() doit être préféré à la place.)

void jsonResponse(array $data, int $statusCode = 200) 
// Méthode à l'ancienne / Réponse avec format personnalisé
jsonResponse(['resultat_operation' => 'ok'], 200);

System Helpers — verifyCsrf() SystemMethod

Vérifie que la requête POST entrante provient d'un formulaire légitime. Renvoie false si csrfField() n'a pas été ajouté au formulaire ou si le jeton est invalide.

bool verifyCsrf(string $token) 
if (!verifyCsrf($_POST['csrf_token'] ?? '')) {
    jsonResponse(['status' => 'error', 'message' => 'Jeton CSRF invalide.'], 403);
}

System Helpers — Outils pratiques SystemMethod

arrayOnly($source, $keys)

Filtre uniquement les clés autorisées d'un tableau (par exemple $_POST). Prévient les vulnérabilités de sécurité d'affectation de masse (mass-assignment).

$data = arrayOnly($_POST, ['nom', 'email', 'telephone']);

dd(...$vars)

Débogage rapide (Dump and Die). Affiche les variables données dans un bloc lisible à l'écran et arrête immédiatement l'exécution de l'application.

dd($utilisateur, $_POST);

API — Contrôle de la méthode HTTP ApiControl

Le tableau $allowedMethods doit être défini avant l'inclusion (require) de ApiControl. ApiControl lit ce tableau et rejette automatiquement les requêtes provenant de méthodes non autorisées avec un 405 Method Not Allowed.

// Un point de terminaison qui n'accepte que GET et POST
$allowedMethods = ['GET', 'POST'];
require_once ... . '/../app/ApiControl.php';

// Un point de terminaison qui n'accepte que DELETE
$allowedMethods = ['DELETE'];
require_once ... . '/../app/ApiControl.php';

Les requêtes OPTIONS preflight pour CORS renvoient automatiquement 200 et le script se termine — aucune intervention manuelle n'est requise.

API — CORS ApiControl (Ligne commentée)

Si vous souhaitez autoriser l'accès à l'API à partir d'autres domaines ou d'applications mobiles, activez le bloc CORS dans ApiControl.php.

// Dans ApiControl.php — activé en supprimant les commentaires
header("Access-Control-Allow-Origin: https://votre-domaine.com");
header("Access-Control-Allow-Methods: GET, POST, OPTIONS");
header("Access-Control-Allow-Headers: Content-Type, Authorization");
⚠️ N'utilisez pas * (tous les domaines) dans un environnement de production (Production). Spécifiez explicitement l'adresse du domaine.

API — Limitation de débit (Rate Limiting) ApiControl (Ligne commentée)

Vous pouvez activer le bloc de limitation de débit (Rate Limiting) dans ApiControl.php pour empêcher les utilisateurs malveillants ou les bots de saturer (flood) l'API. Règle par défaut : 60 requêtes par 60 secondes / IP.

⚠️ Serveur Redis Requis : La fonctionnalité de limitation de débit (Rate Limiting) fonctionne via la classe \Src\Service\RedisService::getInstance() en utilisant Redis. Avant d'activer ce bloc de code, assurez-vous d'avoir installé un service Redis dans votre projet et créé une classe de connexion sous src/Service/. 
// Si plus de 60 requêtes proviennent de la même IP en 60 secondes :
http_response_code(429); // Too Many Requests
echo json_encode(['error' => 'Trop de requêtes. Veuillez patienter.']);

Flux de travail complet : Formulaire de contact (De bout en bout)

Voyons étape par étape comment développer une fonctionnalité de Formulaire de contact selon les normes ArtiFrame, du début à la fin.

  1. Créez le fichier de vue (View) 
    artiframe> make:view contact.php
✔  public/contact.php
✔  public/assets/css/contact.css
✔  public/assets/js/contact.js
  2. Créez le point de terminaison de l'API 
    artiframe> make:api standart api/contact/envoyer.php
  3. Codez le formulaire HTML
    Ajoutez le formulaire suivant au fichier public/contact.php : 
    <form action="/api/contact/envoyer.php" method="POST">
    <?= csrfField() ?>
    <input type="text"  name="nom"      placeholder="Votre nom">
    <input type="email" name="email"  placeholder="E-mail">
    <textarea name="message" placeholder="Votre message"></textarea>
    <button type="submit" data-js="iletisim-gonder">Envoyer</button>
</form>
  4. Lie l'API Fetch avec JavaScript
    Dans le fichier public/assets/js/contact.js : 
    document.querySelector('[data-js="iletisim-gonder"]').addEventListener('click', async (e) => {
    e.preventDefault();
    const formData = new FormData(e.target.closest('form'));
    const res = await fetch('/api/contact/envoyer.php', {
        method: 'POST',
        body: formData
    });
    const data = await res.json();
    console.log(data);
});
  5. Complétez la logique serveur (Backend)
    Dans le fichier public/api/contact/envoyer.php : 
    <?php
$allowedMethods = ['POST'];
require_once $_SERVER['DOCUMENT_ROOT'] . '/../app/ApiControl.php';
use Bin\SystemMethod;

// 1. Validation CSRF
if (!verifyCsrf($_POST['csrf_token'] ?? '')) {
    jsonResponse(['error' => 'Jeton invalide.'], 403);
}

// 2. Nettoyer les données
$nom    = sanitizeString($_POST['nom'] ?? '');
$email  = sanitizeEmail($_POST['email'] ?? '');
$message= sanitizeString($_POST['message'] ?? '');

// 3. Logique métier (Envoyer un e-mail, enregistrer dans la base de données, etc.)
// ...

// 4. Donner une réponse
jsonResponse(['status' => 'success', 'message' => 'Votre message a été reçu.'], 200);
✅ Terminé ! Vous avez créé un flux de formulaire entièrement sécurisé et conforme aux normes grâce à la protection XSS, la validation CSRF, la restriction des méthodes HTTP et l'architecture data-js.
