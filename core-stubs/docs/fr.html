ArtiFrame Documentation

Framework pour des projets PHP natifs évolutifs gérés sans aucune dépendance externe, des règles strictes et une CLI puissante. Aucune dépendance, un écosystème léger et rapide, sans soupe de packages Composer, vous permettant de vous concentrer sur votre logique métier.

Introduction et philosophie

ArtiFrame, "Convention sur la configuration" Il est basé sur le principe de (Règles Avant Configuration). La puissance d’un framework ne vient pas de la richesse des outils qu’il propose, mais de la cohérence de l’ordre qu’il établit.

Zéro frais généraux

Aucune dépendance vis-à-vis de packages ou de bibliothèques Composer tiers. Composer est utilisé uniquement pour exécuter le mécanisme de chargement automatique PSR-4 du projet. Chaque ligne de code vous appartient ; exempt de couches d’abstraction inutiles.

La sécurité avant tout

La protection XSS, la validation CSRF, la désinfection contre l'injection SQL et la vérification des méthodes HTTP sont intégrées par défaut. La sécurité n’est pas une option, c’est une norme.

Ensemble de règles strictes

Un développeur junior qui vient de rejoindre le projet, data-js Comprend l’architecture et la structure des répertoires en quelques minutes. La compatibilité des équipes est garantie au niveau du framework.

Priorité CLI

Il n’est pas nécessaire de créer manuellement des fichiers de vue, d’API ou de classe. La CLI génère des fichiers stub, lie les actifs et maintient la cohérence du projet.

💡 Philosophie de la dépendance : Lors de la création d'un nouveau projet, des packages de composition de renommée mondiale tels que phpmailer, redis, ramsey/uuid sont installés. Cependant, le noyau ArtiFrame n’en dépend pas. Vous pouvez le supprimer quand vous le souhaitez, télécharger vos propres packages et réécrire vos fonctions selon votre propre architecture. ArtiFrame protège votre liberté architecturale tout en réduisant à zéro la dépendance externe.
ℹ️ Licence AGPLv3 : ArtiFrame est open source. Les œuvres dérivées que vous produisez peuvent être utilisées librement, à condition que le code source reste ouvert. L'avis de droit d'auteur ne peut pas être supprimé.

ArtiFrame est un framework open source avec licence AGPLv3. Cependant, des scénarios d'utilisation flexibles ont été conçus pour que les développeurs puissent commercialiser leurs projets et les vendre en source fermée.

Architecture d'amorçage Kritik

ArtiFrame utilise deux bootstrappers complètement indépendants. Cette architecture Problèmes d'en-tête HTML et vulnérabilités de sécurité l’empêche radicalement.

View ViewControl.php

Il est utilisé pour les pages HTML (afficher les fichiers). La séance démarre, ViewMethodInstalle .

// public/profil.php — EN ÜSTE, HTML basmadan önce
<?php
require_once $_SERVER['DOCUMENT_ROOT']
    . '/../app/ViewControl.php';
use Bin\ViewMethod;
?>
<!DOCTYPE html>
...

API ApiControl.php

Utilisé pour les fichiers de point de terminaison d'API. Définit l'en-tête JSON, effectue le contrôle de la méthode HTTP, SystemMethodInstalle .

// public/api/kullanici/getir.php
<?php
// $allowedMethods MUTLAKA require'dan önce tanımlanmalı
$allowedMethods = ['GET'];

require_once $_SERVER['DOCUMENT_ROOT']
    . '/../app/ApiControl.php';

use Bin\SystemMethod;
🚫 ViewControl et ApiControl ne sont jamais mélangés : Si ViewControl est requis pour un fichier API, l'en-tête HTML peut être renvoyé à la place de l'en-tête JSON et l'intégralité de la réponse API sera corrompue. Si ApiControl est requis sur une page HTML, la session ne démarrera pas et la page sera interrompue.

Ensemble de règles Standart

Règle 1 : architecture data-js Kritik

Les événements JavaScript ne sont jamais class ou id on ne peut pas l'écouter. Ce sont des identités visuelles/style. Toutes les interactions JS data-js Il est géré par l'attribut. JavaScript ne plante jamais lorsque CSS supprime une classe.

<!-- ❌ Anti-Pattern — desteklenmez -->
<button id="submitBtn" class="btn">Gönder</button>
// JS: document.getElementById('submitBtn').addEventListener(...)

<!-- ✅ ArtiFrame Standardı -->
<button class="btn btn-primary" data-js="login-submit">Gönder</button>
// JS: document.querySelector('[data-js="login-submit"]').addEventListener(...)

Règle 2 : Architecture thématique

Mode et thèmes sombre/clair, <html> de l'étiquette data-theme Et data-mode Il se gère à travers ses attributs. Les classes corporelles ne sont pas utilisées.

<!-- view.stub şablonundan gelen HTML açılış etiketi -->
<html lang="tr" data-theme="default" data-mode="light">

/* app.css içindeki tema tanımı */
html[data-theme="default"][data-mode="dark"] {
    --bg-color: #0b0c0e;
    --text-main: #ffffff;
}
html[data-theme="default"][data-mode="light"] {
    --bg-color: #ffffff;
    --text-main: #111111;
}

Règle 3 : flux de données sécurisé

Toutes les données provenant de la base de données sont traitées avant d'être transmises au DOM. display() Il est enveloppé avec. Toutes les données arrivant à l'API sont traitées avant d'être traitées. sanitizeString() ou sanitizeInt() Il est nettoyé avec .

Règle 4 : Gestion des erreurs avec APP_ENV

.env dans le dossier APP_ENV La valeur détermine la visibilité des erreurs. En Production, aucun message d’erreur n’est affiché à l’utilisateur.

// config/app-version.php
define('APP_ENV', (int)$_ENV['APP_ENV']); // 1=Debug, 0=Production

if (APP_ENV === 1) {
    ini_set('display_errors', 1);
    error_reporting(E_ALL);
} else {
    ini_set('display_errors', 0);
}

make:api CLI Komutu

Il crée un fichier de point de terminaison d'API en choisissant l'un des deux modèles différents. Avec chaque nouveau fichier API $allowedMethods variable et ApiControl.php Il est livré avec l'exigence prête.

standart — API à action unique

Pour les points de terminaison qui effectuent une seule tâche (connexion, envoi, suppression). La logique métier est écrite directement.

artiframe> make:api standart api/auth/giris.php
<?php
$allowedMethods = ['POST']; // Sadece POST kabul et
require_once $_SERVER['DOCUMENT_ROOT'] . '/../app/ApiControl.php';

use Bin\SystemMethod;

// İş mantığı buraya...
jsonResponse(['status' => 'success'], 200);

switch-case — API multi-actions

Une structure qui gère les opérations CRUD pour un module dans un seul point de terminaison. action Le paramètre détermine quelle opération sera effectuée.

artiframe> make:api switch-case api/kullanici/yonet.php
<?php
$allowedMethods = ['POST'];
require_once $_SERVER['DOCUMENT_ROOT'] . '/../app/ApiControl.php';

use Bin\SystemMethod;

$action = sanitizeString($_POST['action'] ?? '');

switch ($action) {
    case 'create':
        jsonResponse(['status' => 'success', 'message' => 'Oluşturuldu.'], 200);
        break;
    case 'update':
        jsonResponse(['status' => 'success', 'message' => 'Güncellendi.'], 200);
        break;
    case 'delete':
        jsonResponse(['status' => 'success', 'message' => 'Silindi.'], 200);
        break;
    default:
        jsonResponse(['status' => 'error', 'message' => 'Geçersiz action.'], 400);
}

remove CLI Komutu

Supprime en toute sécurité un fichier spécifié. make Il fonctionne à l'opposé des commandes et analyse les dépendances dans le projet et donne des avertissements avant suppression :

  • Si la vue est supprimée : si fichier public/ et fichiers CSS/JS liés à ce fichier public/assets Si tel est le cas, il vous demandera si vous souhaitez également les nettoyer.
  • Si la classe est supprimée : si fichier src/ ou app/ si ci-dessous, public/api/ scanne le répertoire. Il vous avertit en imprimant les fins d'API et les numéros de ligne dans lesquelles la classe que vous avez supprimée est utilisée, mais il ne supprime pas automatiquement les API (pour des raisons de sécurité, vous devez modifier manuellement les API concernées).

PHPMailer (Mail)

📌 Configuration automatique de .env: Lorsque vous exécutez la commande add phpmailer, les paramètres SMTP sont automatiquement ajoutés à votre fichier .env et la classe src/Service/Mailer.php est créée.

Une classe d'encapsulation (Wrapper) beaucoup plus moderne, fluide et sécurisée fonctionnant avec la bibliothèque PHPMailer. Toutes les méthodes fournies sont chaînables.

Méthodes et utilisation

  • ->to('mail@adres.com', 'İsim') : Définit à qui l'e-mail sera envoyé.
  • ->cc('mail@adres.com') : Ajoute des destinataires en copie (Carbon Copy).
  • ->bcc('mail@adres.com') : Ajoute des destinataires en copie cachée (BCC). Les destinataires principaux ne peuvent pas voir ces adresses.
  • ->subject('Konu') : Définit l'objet (le titre) de l'e-mail.
  • ->attach('/path/fatura.pdf', 'Isim.pdf') : Ajoute un fichier physique du serveur (ou temp) en tant que pièce jointe dans l'e-mail.
  • ->embedImage('/path/logo.png', 'logo_cid') : Intègre une image dans l'e-mail pour être utilisée en HTML (<img src="cid:logo_cid">).
  • ->html('HTML Kodu') : Définit le contenu HTML. Crée automatiquement une version texte brut (AltBody) pour la sécurité.
  • ->text('Düz Metin') : Utilisé si vous souhaitez envoyer l'e-mail strictement en texte brut.
  • ->send() : Termine toutes les opérations chaînées et envoie l'e-mail via SMTP. Lance une Exception en cas d'erreur.

Exemple avancé : Modèle PHP (View) et pièce jointe dynamique

Si vous ne souhaitez pas écrire le contenu HTML de l'e-mail directement dans des chaînes, vous pouvez utiliser ob_start() pour inclure un fichier de modèle PHP externe (contenant des variables) et joindre un PDF :

use App\Service\Mailer;

// 1. Vos données dynamiques
$siparisNo = '#90210';
$pdfDosyasi = $_SERVER['DOCUMENT_ROOT'] . '/temp/fatura_90210.pdf';

// 2. Chargement du modèle HTML en externe (Output Buffering)
ob_start();
require_once $_SERVER['DOCUMENT_ROOT'] . '/views/email/siparis.php';
$htmlIcerik = ob_get_clean();

// 3. Envoi de l'e-mail
Mailer::create()
    ->to('musteri@mail.com', 'Ahmet Yılmaz')
    ->bcc('arsiv@sirket.com') // Le client ne peut pas voir cela
    ->subject('Siparişiniz Onaylandı: ' . $siparisNo)
    ->html($htmlIcerik)
    ->attach($pdfDosyasi, 'Siparis_Faturasi.pdf')
    ->send();
