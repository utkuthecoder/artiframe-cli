====== CONNEXION ======

ArtiFrameDocumentation

Framework pour des projets PHP natifs évolutifs gérés sans aucune dépendance externe, des règles strictes et une CLI puissante. Aucune dépendance, un écosystème léger et rapide, sans soupe de packages Composer, vous permettant de vous concentrer sur votre logique métier.

====== INTRODUCTION ET PHILOSOPHIE ======

Introduction et philosophie

ArtiFrame,"Convention sur la configuration"Il est basé sur le principe de (Règles Avant Configuration). La puissance d’un framework ne vient pas de la richesse des outils qu’il propose, mais de la cohérence de l’ordre qu’il établit.

Zéro frais généraux

Aucune dépendance vis-à-vis de packages ou de bibliothèques Composer tiers. Composer est utilisé uniquement pour exécuter le mécanisme de chargement automatique PSR-4 du projet. Chaque ligne de code vous appartient ; exempt de couches d’abstraction inutiles.

La sécurité avant tout

La protection XSS, la validation CSRF, la désinfection contre l'injection SQL et la vérification des méthodes HTTP sont intégrées par défaut. La sécurité n’est pas une option, c’est une norme.

Ensemble de règles strictes

Un développeur junior qui vient de rejoindre le projet,data-jsComprend l’architecture et la structure des répertoires en quelques minutes. La compatibilité des équipes est garantie au niveau du framework.

Priorité CLI

Il n’est pas nécessaire de créer manuellement des fichiers de vue, d’API ou de classe. La CLI génère des fichiers stub, établit des liens d’actifs et maintient la cohérence du projet.

💡 Philosophie de la dépendance :Lors de la création d'un nouveau projet, des packages de composition de renommée mondiale tels que phpmailer, redis, ramsey/uuid sont installés. Cependant, le noyau ArtiFrame n’en dépend pas. Vous pouvez le supprimer quand vous le souhaitez, télécharger vos propres packages et réécrire vos fonctions selon votre propre architecture. ArtiFrame préserve votre liberté architecturale tout en réduisant à zéro la dépendance externe.
ℹ️ Licence AGPLv3 :ArtiFrame est open source. Les œuvres dérivées que vous produisez peuvent être utilisées librement, à condition que le code source reste ouvert. L'avis de droit d'auteur ne peut pas être supprimé.

Gestion intelligente des erreurs API

Si des erreurs 404 (Page introuvable) ou 503 (Mode de maintenance)au point de terminaison de l'API(Par exemple/api/user/get) vient ; Au lieu d'afficher une page HTML au client HTTP (application mobile, frontend), le système définit le code d'état et crée automatiquement un standardErreur JSONrevient. Cela garantit que votre API peut toujours répondre à JSON sans planter.

{
  "status": "error",
  "message": "API Endpoint Not Found",
  "data": []
}
💡 Remarque : capture des erreurs frontales
Le code d'erreur (404, 503, etc.) n'est pas inclus dans les données JSON, mais directement dans le standardDans la réponse réseau HTTP (code d'état)rotatif. De cette façon, vous pouvez détecter les erreurs au niveau de la couche réseau sans avoir à analyser le contenu JSON :
// Exemple d'API de récupération :

    if (!response.ok) {
        console.error("HTTP Hatası:", response.status); // 404 ou 503
    }
});

// Exemple Axios :
axios.get('/api/user/get').catch(error => {
    console.error("HTTP Hatası:", error.response.status); // 404 ou 503
