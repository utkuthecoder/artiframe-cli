ArtiFrame Dokumentation

Framework für skalierbare native PHP-Projekte, die ohne externe Abhängigkeiten, strenge Regeln und eine leistungsstarke CLI verwaltet werden. Keine Abhängigkeiten, ein leichtes und schnelles Ökosystem ohne Composer-Paketsuppe, sodass Sie sich auf Ihre Geschäftslogik konzentrieren können.

Einführung & Philosophie

ArtiFrame, „Konvention statt Konfiguration“ Es basiert auf dem Prinzip (Regeln vor der Konfiguration). Die Leistungsfähigkeit eines Frameworks beruht nicht auf der Vielfalt der Tools, die es bietet, sondern auf der Konsistenz der von ihm festgelegten Ordnung.

Kein Overhead

Keine Abhängigkeiten von Composer-Paketen oder -Bibliotheken von Drittanbietern. Composer wird nur zum Ausführen des projekteigenen PSR-4-Autoloading-Mechanismus verwendet. Jede Codezeile gehört Ihnen; frei von unnötigen Abstraktionsebenen.

Sicherheit steht an erster Stelle

XSS-Schutz, CSRF-Validierung, Bereinigung gegen SQL-Injection und HTTP-Methodenprüfung sind standardmäßig integriert. Sicherheit ist keine Option, sondern ein Standard.

Strenger Regelsatz

Ein Junior-Entwickler, der gerade dem Projekt beigetreten ist, data-js Versteht die Architektur und Verzeichnisstruktur in wenigen Minuten. Die Teamkompatibilität ist auf Framework-Ebene gewährleistet.

CLI-Priorität

Es ist nicht erforderlich, Ansichts-, API- und Klassendateien manuell zu erstellen. Die CLI generiert Stub-Dateien, verknüpft Assets und hält das Projekt konsistent.

💡 Suchtphilosophie: Beim Erstellen eines neuen Projekts werden Composer-Pakete nach Weltstandard wie phpmailer, redis, ramsey/uuid installiert. Der ArtiFrame-Kern ist jedoch nicht von ihnen abhängig. Sie können es jederzeit löschen, Ihre eigenen Pakete herunterladen und Ihre Funktionen entsprechend Ihrer eigenen Architektur neu schreiben. ArtiFrame bewahrt Ihre architektonische Freiheit und reduziert gleichzeitig die externe Abhängigkeit auf Null.
ℹ️ AGPLv3-Lizenz: ArtiFrame ist Open Source. Von Ihnen erstellte abgeleitete Werke dürfen frei verwendet werden, sofern der Quellcode offen bleibt. Der Copyright-Hinweis kann nicht entfernt werden.

Lizenz und Nutzungsbedingungen

ArtiFrame ist ein Open-Source-Framework mit AGPLv3-Lizenz. Es wurden jedoch flexible Nutzungsszenarien entworfen, damit Entwickler ihre Projekte kommerzialisieren und als Closed Source verkaufen können.

🗽 Özgür Ticaret (Endbenutzerprojekte)

Auf den Websites Ihrer Kunden, in internen B2B-Panels, in E-Commerce-Infrastrukturen oder in jedem SaaS/PaaS-Projekt, das dem Endbenutzer dient. Du bist frei Sie können Ihren Code verstecken, verkaufen und urheberrechtlich schützen.

🔄 Fork und neues Framework

Die Kerndateien von ArtiFrame (bin/ Und app/) Wenn Sie für sich oder andere ein neues Framework, eine neue CMS-Infrastruktur oder ein neues Codierungstool erstellen, können Sie dieses neue Produkt ebenfalls verwenden. Open Source Sie müssen es als veröffentlichen.

⚖️ Rechtsdurchsetzungs- und Verstoßsituation

Für den Fall, dass die Kerncodes unter Verstoß gegen die Lizenzbedingungen kopiert, in ein kommerzielles Framework (CMS) mit Closed-Source-Status umgewandelt oder Lizenzhinweise gelöscht werden; Ein solches Vorgehen wird eindeutig als Verletzung des internationalen Urheberrechts und der AGPLv3-Lizenz angesehen. Bei solchen Feststellungen werden rechtliche Verfahren für unautorisierte Kopien und Closed-Source-Derivate direkt umgesetzt.

Bootstrapper-Architektur Kritik

ArtiFrame verwendet zwei völlig unabhängige Bootstrapper. Diese Architektur Probleme mit HTML-Headern und Sicherheitslücken verhindert es radikal.

View ViewControl.php

Es wird für HTML-Seiten (Ansichtsdateien) verwendet. Sitzung beginnt, ViewMethodInstalliert .

// public/profil.php — EN ÜSTE, HTML basmadan önce
<?php
require_once $_SERVER['DOCUMENT_ROOT']
    . '/../app/ViewControl.php';
use Bin\ViewMethod;
?>
<!DOCTYPE html>
...

API ApiControl.php

Wird für API-Endpunktdateien verwendet. Legt den JSON-Header fest, führt die HTTP-Methodensteuerung durch, SystemMethodInstalliert .

// public/api/kullanici/getir.php
<?php
// $allowedMethods MUTLAKA require'dan önce tanımlanmalı
$allowedMethods = ['GET'];

require_once $_SERVER['DOCUMENT_ROOT']
    . '/../app/ApiControl.php';

use Bin\SystemMethod;
🚫 ViewControl und ApiControl werden niemals gemischt: Wenn ViewControl für eine API-Datei erforderlich ist, wird möglicherweise ein HTML-Header anstelle eines JSON-Headers zurückgegeben und die gesamte API-Antwort wird beschädigt. Wenn ApiControl auf einer HTML-Seite erforderlich ist, wird die Sitzung nicht gestartet und die Seite wird unterbrochen.

Regelsatz Standart

Regel 1: data-js-Architektur Kritik

JavaScript-Ereignisse sind niemals vorhanden class oder id kann darüber nicht abgehört werden. Dies sind visuelle/stilistische Identitäten. Alle JS-Interaktionen data-js Es wird durch das Attribut verwaltet. JavaScript stürzt nie ab, wenn CSS eine Klasse löscht.

<!-- ❌ Anti-Pattern — desteklenmez -->
<button id="submitBtn" class="btn">Gönder</button>
// JS: document.getElementById('submitBtn').addEventListener(...)

<!-- ✅ ArtiFrame Standardı -->
<button class="btn btn-primary" data-js="login-submit">Gönder</button>
// JS: document.querySelector('[data-js="login-submit"]').addEventListener(...)

Regel 2: Themenarchitektur

Dunkel/Hell-Modus und Themen, <html> des Etiketts data-theme Und data-mode Es wird über seine Attribute verwaltet. Körperklassen werden nicht verwendet.

<!-- view.stub şablonundan gelen HTML açılış etiketi -->
<html lang="tr" data-theme="default" data-mode="light">

/* app.css içindeki tema tanımı */
html[data-theme="default"][data-mode="dark"] {
    --bg-color: #0b0c0e;
    --text-main: #ffffff;
}
html[data-theme="default"][data-mode="light"] {
    --bg-color: #ffffff;
    --text-main: #111111;
}

Regel 3: Sicherer Datenfluss

Alle aus der Datenbank kommenden Daten werden verarbeitet, bevor sie an das DOM übertragen werden. display() Es ist mit umwickelt. Alle an die API eingehenden Daten werden vor ihrer Verarbeitung verarbeitet. sanitizeString() oder sanitizeInt() Es wird mit gereinigt.

Regel 4: Fehlerbehandlung mit APP_ENV

.env in der Datei APP_ENV Der Wert bestimmt die Fehlersichtbarkeit. In der Produktion wird dem Benutzer keine Fehlermeldung angezeigt.

// config/app-version.php
define('APP_ENV', (int)$_ENV['APP_ENV']); // 1=Debug, 0=Production

if (APP_ENV === 1) {
    ini_set('display_errors', 1);
    error_reporting(E_ALL);
} else {
    ini_set('display_errors', 0);
}

make:api CLI Komutu

Es erstellt eine API-Endpunktdatei, indem es eine von zwei verschiedenen Vorlagen auswählt. Mit jeder neuen API-Datei $allowedMethods variabel und ApiControl.php Es wird mit der erforderlichen Vorbereitung geliefert.

standart – Single-Action-API

Für Endpunkte, die einen einzelnen Job ausführen (Anmelden, Senden, Löschen). Geschäftslogik wird direkt geschrieben.

artiframe> make:api standart api/auth/giris.php
<?php
$allowedMethods = ['POST']; // Sadece POST kabul et
require_once $_SERVER['DOCUMENT_ROOT'] . '/../app/ApiControl.php';

use Bin\SystemMethod;

// İş mantığı buraya...
jsonResponse(['status' => 'success'], 200);

switch-case – Multi-Action-API

Eine Struktur, die CRUD-Vorgänge für ein Modul in einem einzelnen Endpunkt verwaltet. action Der Parameter bestimmt, welcher Vorgang ausgeführt wird.

artiframe> make:api switch-case api/kullanici/yonet.php
<?php
$allowedMethods = ['POST'];
require_once $_SERVER['DOCUMENT_ROOT'] . '/../app/ApiControl.php';

use Bin\SystemMethod;

$action = sanitizeString($_POST['action'] ?? '');

switch ($action) {
    case 'create':
        jsonResponse(['status' => 'success', 'message' => 'Oluşturuldu.'], 200);
        break;
    case 'update':
        jsonResponse(['status' => 'success', 'message' => 'Güncellendi.'], 200);
        break;
    case 'delete':
        jsonResponse(['status' => 'success', 'message' => 'Silindi.'], 200);
        break;
    default:
        jsonResponse(['status' => 'error', 'message' => 'Geçersiz action.'], 400);
}

PHPMailer (Mail)

📌 Automatische .env-Einrichtung: Wenn Sie den Befehl add phpmailer ausführen, werden die SMTP-Einstellungen automatisch zu Ihrer .env-Datei hinzugefügt und die Klasse src/Service/Mailer.php erstellt.

Eine viel modernere, fließende und sichere (CRLF-geschützte) Wrapper-Klasse, die auf der PHPMailer-Bibliothek aufbaut. Alle Methoden der Klasse sind verkettbar (chainable).

Methoden und Verwendung

  • ->to('mail@adres.com', 'İsim') : Legt fest, an wen die E-Mail gesendet wird.
  • ->cc('mail@adres.com') : Fügt CC-Empfänger (Carbon Copy) hinzu.
  • ->bcc('mail@adres.com') : Fügt BCC-Empfänger (Blind Carbon Copy) hinzu. Primäre Empfänger können diese nicht sehen.
  • ->subject('Konu') : Legt den Betreff (Titel) der E-Mail fest.
  • ->attach('/path/fatura.pdf', 'Isim.pdf') : Fügt eine physische Datei vom Server (oder Temp) als Anhang zur E-Mail hinzu.
  • ->embedImage('/path/logo.png', 'logo_cid') : Bettet ein Bild in die E-Mail ein, das im HTML verwendet wird (<img src="cid:logo_cid">).
  • ->html('HTML Kodu') : Legt den HTML-Inhalt der E-Mail fest. Erstellt automatisch eine reine Textversion (AltBody).
  • ->text('Düz Metin') : Wird verwendet, wenn die E-Mail ausschließlich als reiner Text gesendet werden soll.
  • ->send() : Schließt alle Operationen ab und sendet die E-Mail über SMTP. Wirft bei Fehler eine Exception.

Erweitertes Beispiel: PHP-Vorlage (View) und dynamischer Dateianhang

Wenn Sie den HTML-Inhalt nicht direkt in Strings schreiben möchten, können Sie ob_start() verwenden, um eine externe PHP-Vorlagendatei (mit Variablen) einzubinden und ein dynamisch generiertes PDF anzuhängen:

use App\Service\Mailer;

// 1. Ihre dynamischen Daten
$siparisNo = '#90210';
$pdfDosyasi = $_SERVER['DOCUMENT_ROOT'] . '/temp/fatura_90210.pdf';

// 2. HTML-Vorlage extern laden (Output Buffering)
ob_start();
require_once $_SERVER['DOCUMENT_ROOT'] . '/views/email/siparis.php';
$htmlIcerik = ob_get_clean();

// 3. E-Mail senden
Mailer::create()
    ->to('musteri@mail.com', 'Ahmet Yılmaz')
    ->bcc('arsiv@sirket.com') // Der Kunde kann dies nicht sehen
    ->subject('Siparişiniz Onaylandı: ' . $siparisNo)
    ->html($htmlIcerik)
    ->attach($pdfDosyasi, 'Siparis_Faturasi.pdf')
    ->send();

Im Live-Modus (APP_ENV = 0) werden Fehler ausgeblendet und nur die klare Nachricht angezeigt, die Sie eingegeben haben.

try {
    // Veritabanı sorguları...
} catch (\Exception $e) {

}

// 8-stellige reine Buchstaben ('c': klein, 'C': groß, 'cC': gemischt)
$code = otpStr(8, 'C'); // PKLMDZRA

// 6-stellig alphanumerisch
$code = otpMix(6, 'C'); // 9A4X2Z

API – HTTP-Methodensteuerung ApiControl

$allowedMethods Array von ApiControl erfordern vor muss definiert werden. ApiControl blockiert automatisch Anfragen von unzulässigen Methoden, indem es diese Zeichenfolge liest. 405 Method Not Allowed Er lehnt es mit ab.

// Sadece GET ve POST kabul eden bir endpoint
$allowedMethods = ['GET', 'POST'];
require_once ... . '/../app/ApiControl.php';

// Sadece DELETE kabul eden bir endpoint
$allowedMethods = ['DELETE'];
require_once ... . '/../app/ApiControl.php';

Vorflug OPTIONS automatische Anfragen für CORS 200 kehrt zurück und das Skript wird beendet – kein manueller Eingriff erforderlich.

API – CORS ApiControl (Yorum Satırı)

Wenn Sie den API-Zugriff von anderen Domänen oder mobilen Anwendungen zulassen möchten ApiControl.php Aktivieren Sie darin den CORS-Block.

// ApiControl.php içinde — açıklama kaldırılarak aktifleştirilir
header("Access-Control-Allow-Origin: https://sizin-domaininiz.com");
header("Access-Control-Allow-Methods: GET, POST, OPTIONS");
header("Access-Control-Allow-Headers: Content-Type, Authorization");
⚠️ Im Produktionsumfeld * Nicht verwenden (alle Domänen). Geben Sie die Domänenadresse deutlich an.

API – Ratenbegrenzung ApiControl (Yorum Satırı)

Um zu verhindern, dass böswillige Benutzer oder Bots die API überfluten ApiControl.php Sie können darin den Rate-Limiting-Block aktivieren. Standardregel: 60 Anfragen/IP in 60 Sekunden.

⚠️ Redis-Server erforderlich: Ratenbegrenzungsfunktion \Src\Service\RedisService::getInstance() Es funktioniert mit der Redis-Klasse. Stellen Sie vor dem Öffnen dieses Codeblocks sicher, dass Sie in Ihrem Projekt einen Redis-Dienst eingerichtet haben src/Service/ Stellen Sie sicher, dass Sie unten eine Verbindungsklasse erstellen
