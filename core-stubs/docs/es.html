ArtiFrame Documentación

Un framework escalable para proyectos PHP nativos, gestionado con una potente CLI, cero dependencias externas y reglas estrictas. Sin dependencias, libre del caos de paquetes de composer, un ecosistema ligero y rápido que te permite centrarte en tu lógica de negocio.

Introducción y Filosofía

ArtiFrame se basa en el principio de "Convention over Configuration" (Convención sobre Configuración). El poder de un framework no proviene de la abundancia de herramientas que ofrece, sino de la coherencia del orden que establece.

Cero Sobrecarga

Cero dependencias de paquetes Composer de terceros o bibliotecas. Composer se utiliza únicamente para ejecutar el mecanismo de carga automática (autoloading) PSR-4 del propio proyecto. Cada línea de código es tuya; libre de capas de abstracción innecesarias.

La Seguridad es lo Primero

La protección XSS, la verificación CSRF, la sanitización contra inyección SQL y el control de métodos HTTP vienen incorporados por defecto. La seguridad no es una opción, es un estándar.

Conjunto de Reglas Estrictas

Un desarrollador junior que se une al proyecto comprende la arquitectura data-js y la estructura de directorios en minutos. La armonía del equipo está garantizada a nivel de framework.

CLI Primero

No hay que crear archivos de vistas, API o clases manualmente. La CLI los genera a partir de archivos stub, establece enlaces de recursos y mantiene el proyecto coherente.

ℹ️ Licencia AGPLv3: ArtiFrame es de código abierto. Los trabajos derivados que produzcas pueden usarse libremente, siempre que el código fuente permanezca abierto. El aviso de copyright no puede eliminarse.

Instalación

La CLI de ArtiFrame se instala como una herramienta PHP global. Se instala una vez y se utiliza en cada proyecto.

1. Instalar la Herramienta CLI Globalmente

# Instalación global vía NPM
npm install -g @artilingo/artiframe-cli

# Verificar la instalación
artiframe

2. Shell Interactivo

Simplemente escribe artiframe en el terminal y presiona Enter. La CLI no se cierra; se abre un shell interactivo que escucha comandos continuamente:

==================================================
        ArtiFrame CLI Interactive Shell v1.0.0
==================================================
Type 'help' for commands, or 'exit' to quit.

artiframe>

3. Iniciar un Nuevo Proyecto

artiframe> new mi-proyecto

Este comando crea el directorio mi-proyecto/ y copia toda la estructura del esqueleto en él: app/, bin/, config/, public/, src/, .env.example y la primera página index.php.

Durante la creación del proyecto, la CLI te preguntará interactivamente por el nombre del proyecto (package), descripción (description), información del autor (author), tipo (type) y licencia de código abierto (license), e insertará esta información en el archivo composer.json del nuevo proyecto.

¡Cuando termina el proceso, se abre automáticamente una nueva ventana de terminal en el directorio del proyecto y la CLI de artiframe se inicia lista en ese proyecto!

4. Configuración del Entorno

cp .env.example .env

Abre tu archivo .env y completa la información de la base de datos y de la aplicación. Este archivo nunca se añade al control de versiones.

⚠️ Configuración del Servidor Web: Apunta el document root de Apache/Nginx a la carpeta /public/. Otros directorios nunca deben ser accesibles externamente.

Estructura de Directorios

La arquitectura generada cuando se inicia el proyecto; garantiza una clara separación de responsabilidades (SoC).

nombre-proyecto/ ├── app/ # Capa de infraestructura │ ├── ViewControl.php # Bootstrapper de Vista (página HTML) │ ├── ApiControl.php # Bootstrapper de endpoint de API │ ├── Database.php # Conexión a base de datos basada en PDO │ ├── DotEnv.php # Lector de .env │ └── R2Manager.php # Administrador de archivos de Cloudflare R2 │ ├── bin/ # ⚠️ Sistema central — no editar directamente │ ├── SystemMethod.php # Ayudantes globales de API/Backend │ ├── ViewMethod.php # Ayudantes globales de Vista/Frontend │ └── stubs/ # Archivos de plantilla usados por la CLI │ ├── view.stub │ ├── api-standart.stub │ ├── api-switch-case.stub │ └── class.stub │ ├── config/ # Archivos de configuración │ └── app-version.php # Constantes APP_VERSION y APP_ENV │ ├── public/ # ← Único directorio abierto del servidor web │ ├── assets/ │ │ ├── css/ # Archivos CSS específicos de Vista │ │ └── js/ # Archivos JS específicos de Vista │ ├── includes/ # Componentes compartidos │ │ ├── head.php │ │ ├── header.php │ │ └── footer.php │ ├── api/ # Archivos de endpoint de API │ └── index.php # Página principal │ ├── src/ # Lógica de negocio y clases ├── .env # Variables de entorno (no entra en git) ├── .env.example # Plantilla — entra en git └── kilavuz.html # Este documento
🚫 No toques el directorio bin/: Los archivos dentro de bin/ son el núcleo del framework. La lógica de negocio específica del proyecto no se añade aquí. Las clases y servicios que añadirás van bajo src/, los componentes de infraestructura van bajo app/.

Arquitectura Bootstrapper Crítico

ArtiFrame utiliza dos bootstrappers completamente independientes. Esta arquitectura evita radicalmente problemas de encabezado HTML y vulnerabilidades de seguridad.

Vista ViewControl.php

Se utiliza para páginas HTML (archivos de vista). Inicia sesión, carga ViewMethod.

// public/perfil.php — EN LA PARTE SUPERIOR, antes de imprimir HTML
<?php
require_once $_SERVER['DOCUMENT_ROOT']
    . '/../app/ViewControl.php';
use Bin\ViewMethod;
?>
<!DOCTYPE html>
...

API ApiControl.php

Se utiliza para archivos de endpoint de API. Configura el encabezado JSON, comprueba el método HTTP, carga SystemMethod.

// public/api/usuario/obtener.php
<?php
// $allowedMethods DEBE definirse antes del require
$allowedMethods = ['GET'];

require_once $_SERVER['DOCUMENT_ROOT']
    . '/../app/ApiControl.php';

use Bin\SystemMethod;
🚫 ViewControl y ApiControl nunca se mezclan: Si ViewControl es requerido en un archivo de API, puede devolver un encabezado HTML en lugar de JSON y arruinar toda la respuesta de la API. Si ApiControl es requerido en una página HTML, la sesión no se inicia y la página se rompe.

Conjunto de Reglas Estándar

Regla 1: Arquitectura data-js Crítico

Los eventos de JavaScript nunca deben ser escuchados a través de un class o un id. Estas son identidades visuales / de estilo. Todas las interacciones de JS se gestionan mediante el atributo data-js. Cuando CSS elimina una clase, JavaScript nunca se bloquea.

<!-- ❌ Anti-Patrón — no soportado -->
<button id="submitBtn" class="btn">Enviar</button>
// JS: document.getElementById('submitBtn').addEventListener(...)

<!-- ✅ Estándar ArtiFrame -->
<button class="btn btn-primary" data-js="login-submit">Enviar</button>
// JS: document.querySelector('[data-js="login-submit"]').addEventListener(...)

Regla 2: Arquitectura de Temas

El modo Oscuro/Claro y los temas se gestionan mediante los atributos data-theme y data-mode de la etiqueta <html>. No se utilizan clases en body.

<!-- etiqueta HTML de apertura de la plantilla view.stub -->
<html lang="es" data-theme="default" data-mode="light">

/* Definición del tema en app.css */
html[data-theme="default"][data-mode="dark"] {
    --bg-color: #0b0c0e;
    --text-main: #ffffff;
}
html[data-theme="default"][data-mode="light"] {
    --bg-color: #ffffff;
    --text-main: #111111;
}

Regla 3: Flujo de Datos Seguro

Cada dato proveniente de la base de datos se envuelve con display() antes de imprimirse en el DOM. Cada dato que llega a la API se limpia con sanitizeString() o sanitizeInt() antes de ser procesado.

Regla 4: Manejo de Errores con APP_ENV

El valor APP_ENV en el archivo .env determina la visibilidad de los errores. En Producción, el mensaje de error no se muestra al usuario.

// config/app-version.php
define('APP_ENV', (int)$_ENV['APP_ENV']); // 1=Debug, 0=Producción

if (APP_ENV === 1) {
    ini_set('display_errors', 1);
    error_reporting(E_ALL);
} else {
    ini_set('display_errors', 0);
}

Ecosistema CLI

La CLI de ArtiFrame abre un shell interactivo cuando se escribe artiframe en el terminal. Todos los comandos se ejecutan dentro de este shell. Los comandos también pueden ejecutarse una sola vez.

# Modo interactivo (recomendado)
artiframe
artiframe> make:view admin/usuarios.php

# Modo de una sola ejecución
artiframe make:view admin/usuarios.php

new Comando CLI

Crea un nuevo proyecto ArtiFrame. Genera todo el esqueleto de directorios, archivos bootstrapper y la página index inicial.

artiframe> new nombre-proyecto

Proceso Interactivo: Cuando se ejecuta el comando, te hace preguntas sobre los metadatos del archivo composer.json del proyecto (Nombre del Paquete, Descripción, Autor, Tipo, Licencia). Todos los detalles y licencias se determinan en esta etapa.

Terminal Automática: Después de crear con éxito el proyecto, se abre automáticamente una nueva ventana de terminal ubicada en el directorio del proyecto y se inicia artiframe, dependiendo de tu sistema operativo.

Estructura generada:

nombre-proyecto/ ├── app/ (ViewControl.php, ApiControl.php, Database.php, DotEnv.php) ├── bin/ (SystemMethod.php, ViewMethod.php, stubs/) ├── config/ (app-version.php) ├── public/ (index.php, assets/, includes/, api/) ├── src/ ├── .env.example └── kilavuz.html

make:view Comando CLI

Crea un nuevo archivo de página (vista) y sus recursos CSS/JS específicos. Los recursos se vinculan automáticamente a la página y se aplica la invalidación de caché (cache-busting) con ?v=APP_VERSION.

artiframe> make:view admin/usuarios.php

Archivos creados:

✔  public/admin/usuarios.php
✔  public/assets/css/admin/usuarios.css
✔  public/assets/js/admin/usuarios.js

El archivo de vista generado viene con ViewControl requerido al principio, incluye head/header/footer añadidos y los enlaces CSS/JS vinculados con cache-busting.

make:api Comando CLI

Crea un archivo de endpoint de API eligiendo una de dos plantillas. En cada nuevo archivo de API, la variable $allowedMethods y el require de ApiControl.php vienen listos.

standart — API de Acción Única

Para endpoints que hacen una sola cosa (login, enviar, eliminar). La lógica de negocio se escribe directamente.

artiframe> make:api standart api/auth/login.php
<?php
$allowedMethods = ['POST']; // Solo aceptar POST
require_once $_SERVER['DOCUMENT_ROOT'] . '/../app/ApiControl.php';

use Bin\SystemMethod;

// Lógica de negocio aquí...
jsonResponse(['status' => 'success'], 200);

switch-case — API Multi-Acción

Estructura que gestiona operaciones CRUD para un módulo en un solo endpoint. La operación a realizar está determinada por el parámetro action.

artiframe> make:api switch-case api/usuario/gestionar.php
<?php
$allowedMethods = ['POST'];
require_once $_SERVER['DOCUMENT_ROOT'] . '/../app/ApiControl.php';

use Bin\SystemMethod;

$action = sanitizeString($_POST['action'] ?? '');

switch ($action) {
    case 'create':
        jsonResponse(['status' => 'success', 'message' => 'Creado.'], 200);
        break;
    case 'update':
        jsonResponse(['status' => 'success', 'message' => 'Actualizado.'], 200);
        break;
    case 'delete':
        jsonResponse(['status' => 'success', 'message' => 'Eliminado.'], 200);
        break;
    default:
        jsonResponse(['status' => 'error', 'message' => 'Acción inválida.'], 400);
}

make:class Comando CLI

Crea un nuevo archivo de clase PHP con el namespace y boilerplate listo. El namespace se determina automáticamente por la ruta de la clase. Si se utiliza un directorio distinto a app/ y src/ (por ejemplo, private/), la CLI ejecuta automáticamente el script composer dump-autoload en segundo plano.

artiframe> make:class src/Service/EmailService.php

Si no se especifica el directorio de la clase, el comando devuelve un error:

artiframe> make:class
❌ Error: ¡Se debe especificar el directorio de la clase! (ej: /app o /src)
Ejemplo: /src/Service/PaymentService

View Helpers — display() ViewMethod

Aplica protección XSS obligatoria al imprimir datos provenientes de la base de datos o entrada de usuario en el DOM. En lugar de lanzar error para valores nulos o vacíos, devuelve un valor por defecto.

string display(mixed $data, string $default = '')
💡 Consejo: Uso de $default
El segundo parámetro ($default) es el texto de rescate que se imprimirá en pantalla cuando los datos provenientes de la base de datos estén vacíos (null, false, cadena vacía). Por ejemplo, si usas display($nombre, 'Sin Nombre') para un usuario que no tiene datos de nombre, tu página mostrará un contenido significativo en lugar de horribles espacios en blanco. 
<!-- ❌ Inseguro — Crea vulnerabilidad XSS -->
<h1><?= $user['nombre'] ?></h1>

<!-- ✅ Uso Seguro de ArtiFrame -->
<h1><?= display($user['nombre'], 'Usuario Anónimo') ?></h1>

View Helpers — escapeUrl() ViewMethod

Se utiliza al imprimir enlaces recibidos de los usuarios (por ejemplo, sitios web de perfil) dentro de <a href="..."> o <img src="...">. Evita la ejecución de código a través del enlace neutralizando payloads peligrosos como javascript:alert(1) (Stored XSS).

string escapeUrl(string $url) 
<!-- ❌ Inseguro — El código JS puede filtrarse a través de la URL -->
<a href="<?= $user['website'] ?>">Visitar Sitio</a>

<!-- ✅ Uso Seguro de ArtiFrame -->
<a href="<?= escapeUrl($user['website']) ?>">Visitar Sitio</a>

View Helpers — csrfField() ViewMethod

Añade un campo de token oculto contra ataques CSRF a los formularios HTML. Es obligatorio usarlo en toda página que contenga un formulario POST.

string csrfField() 
<form action="/api/guardar.php" method="POST">
    <?= csrfField() ?>   <!-- Obligatorio por seguridad -->
    <input type="text" name="nombre">
    <button type="submit" data-js="guardar-btn">Guardar</button>
</form>

View Helpers — Funciones de Fecha ViewMethod

Procesa cadenas de fecha en formato Y-m-d H:i:s de la base de datos o valores de marca de tiempo UNIX. Todas las salidas de texto están localizadas por idioma (tr, en, de, fr, es).

FunciónEjemplo de SalidaDescripción

formatDate($date, $format)24.07.2026 14:30Formato personalizado

💡 Entendiendo los Parámetros: $format y $lang
  • $format (Formato): Se usa solo con la función formatDate(). Acepta letras estándar de fecha PHP. (Ejemplo: 'd/m/Y' ➔ 24/07/2026, o 'H:i' ➔ 15:30). Permite crear tu propio patrón de fecha cuando otras funciones (day, year, etc.) no son suficientes.
  • $lang (Idioma): Se usa en funciones que contienen texto en su salida (nombre del mes, la palabra "hace"). Si lo dejas en blanco, el sistema funcionará en 'tr' (Turco) por defecto. Si estás creando un proyecto multilingüe, solo ingresa el código de idioma (tr, en, de, fr, es) en el segundo parámetro. (Ej: timeAgo($fecha, 'es') ➔ hace 5 minutos)

<!-- Fecha completa por idioma -->

<!-- Salida: 24 Temmuz 2026 -->

<!-- Visualización de tiempo estilo redes sociales -->
<span><?= timeAgo($fecha, 'en') ?></span>
<!-- Salida: 5 minutes ago -->

<span><?= timeAgo($fecha, 'es') ?></span>
<!-- Salida: hace 5 minutos -->

System Helpers — apiResponse() SystemMethod

Es el generador de salidas JSON estándar y universal de ArtiFrame. Debe usarse siempre al enviar datos de APIs a JavaScript. Estandariza el proceso de desarrollo enviando siempre un objeto consistente (status, message, data) al desarrollador JS (Frontend).

void apiResponse(string $status, string $message, array $data = [], \Throwable $exception = null)
💡 Gestión Inteligente de Errores (Soporte APP_ENV)
Si envías un $e (Exception) al 4º parámetro; estando en modo APP_ENV = 1 (Debug), se imprimirá el error real de PHP, la línea y la ruta del archivo en lugar del mensaje escrito por el usuario. Sin embargo, cuando el servidor se pone en modo APP_ENV = 0 (Prod), el sistema oculta automáticamente los registros de la Excepción y solo devuelve tu mensaje limpio de "Ocurrió un error". 
// Respuesta exitosa
apiResponse('success', 'Usuario guardado.', ['id' => $newId]);

// Gestión inteligente de errores con Try-Catch
try {
    // Operaciones de base de datos...
} catch (\Exception $e) {
    // En modo Prod: "Hubo un problema durante el registro."
    // En modo Debug: "SQL Error: duplicate key... (Archivo: user.php Línea: 45)"
    apiResponse('error', 'Hubo un problema durante el registro.', [], $e);
}

System Helpers — jsonResponse() SystemMethod

Configura el encabezado JSON, proporciona el código de estado HTTP e imprime la salida con json_encode. (Por lo general, no se usa directamente; debe preferirse apiResponse() en su lugar).

void jsonResponse(array $data, int $statusCode = 200) 
// Forma antigua / Respuesta con formato personalizado
jsonResponse(['resultado_operacion' => 'ok'], 200);

System Helpers — verifyCsrf() SystemMethod

Verifica que la petición POST entrante provenga de un formulario legítimo. Si no se agregó csrfField() al formulario o el token no es válido, devuelve false.

bool verifyCsrf(string $token) 
if (!verifyCsrf($_POST['csrf_token'] ?? '')) {
    jsonResponse(['status' => 'error', 'message' => 'Token CSRF inválido.'], 403);
}

Filtra solo las claves permitidas de un arreglo (por ejemplo, $_POST). Previene vulnerabilidades de seguridad de asignación masiva (mass-assignment).

$data = arrayOnly($_POST, ['nombre', 'email', 'telefono']);

Depuración rápida (Dump and Die). Imprime en pantalla las variables dadas en un bloque legible y detiene instantáneamente la ejecución de la aplicación.

dd($kullanici, $_POST);

API — Control de Métodos HTTP ApiControl

El arreglo $allowedMethods debe definirse antes del require de ApiControl. ApiControl lee este arreglo y rechaza automáticamente las peticiones de métodos no permitidos con 405 Method Not Allowed.

// Un endpoint que solo acepta GET y POST
$allowedMethods = ['GET', 'POST'];
require_once ... . '/../app/ApiControl.php';

// Un endpoint que solo acepta DELETE
$allowedMethods = ['DELETE'];
require_once ... . '/../app/ApiControl.php';

Las peticiones Preflight OPTIONS devuelven automáticamente 200 para CORS y el script termina — no requiere intervención manual.

API — CORS ApiControl (Línea Comentada)

Si deseas permitir el acceso a la API desde otros dominios o aplicaciones móviles, activa el bloque CORS dentro de ApiControl.php.

// En ApiControl.php — se activa quitando los comentarios
header("Access-Control-Allow-Origin: https://tu-dominio.com");
header("Access-Control-Allow-Methods: GET, POST, OPTIONS");
header("Access-Control-Allow-Headers: Content-Type, Authorization");
⚠️ No uses * (todos los dominios) en un entorno de Producción. Especifica explícitamente la dirección del dominio.

API — Rate Limiting ApiControl (Línea Comentada)

Para evitar que usuarios malintencionados o bots inunden (flood) la API, puedes activar el bloque Rate Limiting en ApiControl.php. Regla predeterminada: 60 peticiones por IP en 60 segundos.

⚠️ Servidor Redis es Necesario: La función de Rate Limiting (límite de velocidad) funciona utilizando Redis a través de la clase \Src\Service\RedisService::getInstance(). Antes de habilitar este bloque de código, asegúrate de haber instalado un servicio Redis en tu proyecto y de haber creado una clase de conexión bajo src/Service/. 
// Si hay más de 60 peticiones desde la misma IP en 60 segundos:
http_response_code(429); // Too Many Requests
echo json_encode(['error' => 'Demasiadas peticiones. Por favor, espere.']);

Flujo de Trabajo Completo: Formulario de Contacto (End-to-End)

Veamos paso a paso cómo desarrollarías una funcionalidad de Formulario de Contacto de principio a fin según los estándares de ArtiFrame.

  1. Crea el Archivo de Vista 
    artiframe> make:view contacto.php
✔  public/contacto.php
✔  public/assets/css/contacto.css
✔  public/assets/js/contacto.js
  2. Crea el Endpoint de API 
    artiframe> make:api standart api/contacto/enviar.php
  3. Codifica el Formulario HTML
    Añade el siguiente formulario al archivo public/contacto.php: 
    <form action="/api/contacto/enviar.php" method="POST">
    <?= csrfField() ?>
    <input type="text"  name="nombre"      placeholder="Tu Nombre">
    <input type="email" name="correo"  placeholder="Correo Electrónico">
    <textarea name="mensaje" placeholder="Tu Mensaje"></textarea>
    <button type="submit" data-js="contacto-enviar">Enviar</button>
</form>
  4. Vincula Fetch API con JavaScript
    En el archivo public/assets/js/contacto.js: 
    document.querySelector('[data-js="contacto-enviar"]').addEventListener('click', async (e) => {
    e.preventDefault();
    const formData = new FormData(e.target.closest('form'));
    const res = await fetch('/api/contacto/enviar.php', {
        method: 'POST',
        body: formData
    });
    const data = await res.json();
    console.log(data);
});
  5. Completa la Lógica del Servidor (Backend)
    En el archivo public/api/contacto/enviar.php: 
    <?php
$allowedMethods = ['POST'];
require_once $_SERVER['DOCUMENT_ROOT'] . '/../app/ApiControl.php';
use Bin\SystemMethod;

// 1. Verificación CSRF
if (!verifyCsrf($_POST['csrf_token'] ?? '')) {
    jsonResponse(['error' => 'Token inválido.'], 403);
}

// 2. Limpiar los Datos
$nombre     = sanitizeString($_POST['nombre'] ?? '');
$correo = sanitizeEmail($_POST['correo'] ?? '');
$mensaje  = sanitizeString($_POST['mensaje'] ?? '');

// 3. Lógica de Negocio (Enviar mail, Guardar en BD, etc.)
// ...

// 4. Dar Respuesta
jsonResponse(['status' => 'success', 'message' => 'Tu mensaje ha sido recibido.'], 200);
✅ ¡Completado! Has creado un flujo de formulario completamente seguro y que cumple con los estándares, con protección XSS, verificación CSRF, restricción de métodos HTTP y arquitectura data-js.
