ArtiFrame Documentación

Marco para proyectos PHP nativos escalables administrados sin dependencias externas, reglas estrictas y una potente CLI. Sin dependencias, un ecosistema ligero y rápido libre de sopa de paquetes de compositores, lo que le permite centrarse en su lógica empresarial.

Introducción y Filosofía

marco artístico, "Convención sobre configuración" Se basa en el principio de (Reglas antes de la configuración). El poder de un marco no proviene de la riqueza de las herramientas que ofrece, sino de la coherencia del orden que establece.

Cero gastos generales

Cero dependencias de paquetes o bibliotecas de Composer de terceros. Composer se utiliza únicamente para ejecutar el mecanismo de carga automática PSR-4 propio del proyecto. Cada línea de código es tuya; libre de capas innecesarias de abstracción.

La seguridad es lo primero

La protección XSS, la validación CSRF, la desinfección contra inyección SQL y la verificación de métodos HTTP están integradas de forma predeterminada. La seguridad no es una opción, es un estándar.

Conjunto de reglas estrictas

Un desarrollador junior que acaba de unirse al proyecto, data-js Entiende la arquitectura y la estructura de directorios en minutos. La compatibilidad del equipo está garantizada a nivel de marco.

Prioridad CLI

No es necesario crear manualmente archivos de vista, API o clase. La CLI genera archivos resguardo, vincula activos y mantiene la coherencia del proyecto.

💡 Filosofía de las Adicciones: Al crear un nuevo proyecto, se instalan paquetes de compositores estándar mundial como phpmailer, redis, ramsey/uuid. Sin embargo, el núcleo de ArtiFrame no depende de ellos. Puedes eliminarlo cuando quieras, descargar tus propios paquetes y reescribir tus funciones de acuerdo con tu propia arquitectura. ArtiFrame preserva su libertad arquitectónica al tiempo que reduce la dependencia externa a cero.
ℹ️ Licencia AGPLv3: ArtiFrame es de código abierto. Las obras derivadas que usted produzca se pueden utilizar libremente, siempre que el código fuente permanezca abierto. El aviso de derechos de autor no se puede eliminar.

Licencia y términos de uso

ArtiFrame es un framework de código abierto con licencia AGPLv3. Sin embargo, se han diseñado escenarios de uso flexibles para que los desarrolladores puedan comercializar sus proyectos y venderlos como código cerrado.

🗽 Özgür Ticaret (Proyectos de usuario final)

En las webs de tus clientes, paneles internos B2B, infraestructuras de E-Commerce o cualquier proyecto SaaS/PaaS que sirva al usuario final. eres libre Puede ocultar su código, venderlo y protegerlo con derechos de autor.

🔄 Bifurcación y nuevo marco

Los archivos principales de ArtiFrame (bin/ Y app/) Si está produciendo un nuevo marco, infraestructura CMS o herramienta de codificación para usted o para otros, también puede utilizar este nuevo producto. Código abierto Tienes que publicarlo como .

⚖️ Situación de aplicación e infracción legal

En caso de que los códigos principales se copien en violación de los términos de la licencia, se conviertan en un marco comercial (CMS) con estado de código cerrado o se eliminen los avisos de licencia; Esta acción se considerará claramente una violación de los derechos de autor internacionales y de la licencia AGPLv3. Arquitectura previa Kritik

ArtiFrame utiliza dos bootstrappers completamente independientes. esta arquitectura Problemas de encabezado HTML y vulnerabilidades de seguridad lo impide radicalmente.

Se utiliza para páginas HTML (ver archivos). Comienza la sesión, ViewMethodSe instala.

require_once $_SERVER['DOCUMENT_ROOT']
    . '/../app/ViewControl.php';
use Bin\ViewMethod;
?>
<!DOCTYPE html>

API ApiControl.php

Se utiliza para archivos de punto final API. Establece el encabezado JSON, realiza el control del método HTTP, SystemMethodSe instala.

// public/api/kullanici/getir.php
<?php
// $allowedMethods MUTLAKA require'dan önce tanımlanmalı

Si se requiere ApiControl en una página HTML, la sesión no se iniciará y la página se interrumpirá.

Conjunto de reglas Standart

Regla 1: Arquitectura data-js Kritik

Los eventos de JavaScript nunca son class o id No se puede escuchar por encima de él. Estas son identidades visuales/de estilo. Todas las interacciones JS data-js Está gestionado por el atributo. JavaScript nunca falla cuando CSS elimina una clase.

<!-- ❌ Anti-Pattern — desteklenmez -->
<button id="submitBtn" class="btn">Gönder</button>
// JS: document.getElementById('submitBtn').addEventListener(...)

<!-- ✅ ArtiFrame Standardı -->
<button class="btn btn-primary" data-js="login-submit">Gönder</button>
// JS: document.querySelector('[data-js="login-submit"]').addEventListener(...)

Regla 2: Arquitectura temática

Modo y temas oscuro/claro, <html> de la etiqueta data-theme Y data-mode Se gestiona a través de sus atributos. No se utilizan clases de cuerpo.

<!-- view.stub şablonundan gelen HTML açılış etiketi -->
<html lang="tr" data-theme="default" data-mode="light">

/* app.css içindeki tema tanımı */
html[data-theme="default"][data-mode="dark"] {
    --bg-color: #0b0c0e;
    --text-main: #ffffff;
}
html[data-theme="default"][data-mode="light"] {
    --bg-color: #ffffff;
    --text-main: #111111;
}

Regla 3: flujo de datos seguro

Todos los datos provenientes de la base de datos se procesan antes de enviarse al DOM. display() Está envuelto con. Todos los datos que llegan a la API se procesan antes de procesarse. sanitizeString() o sanitizeInt() Se limpia con .

Regla 4: Manejo de errores con APP_ENV

.env en el archivo APP_ENV El valor determina la visibilidad del error. En producción, no se muestra ningún mensaje de error al usuario.

// config/app-version.php
define('APP_ENV', (int)$_ENV['APP_ENV']); // 1=Debug, 0=Production

if (APP_ENV === 1) {
    ini_set('display_errors', 1);
    error_reporting(E_ALL);
} else {
    ini_set('display_errors', 0);
}

make:api CLI Komutu

Crea un archivo de punto final API eligiendo una de dos plantillas diferentes. Con cada nuevo archivo API $allowedMethods variables y ApiControl.php Viene con el requisito listo.

standart — API de acción única

Para puntos finales que realizan un solo trabajo (iniciar sesión, enviar, eliminar). La lógica empresarial se escribe directamente.

artiframe> make:api standart api/auth/giris.php
<?php
$allowedMethods = ['POST']; // Sadece POST kabul et
require_once $_SERVER['DOCUMENT_ROOT'] . '/../app/ApiControl.php';

use Bin\SystemMethod;

// İş mantığı buraya...
jsonResponse(['status' => 'success'], 200);

switch-case — API de acción múltiple

Una estructura que gestiona las operaciones CRUD para un módulo en un único punto final. action El parámetro determina qué operación se realizará.

artiframe> make:api switch-case api/kullanici/yonet.php
<?php
$allowedMethods = ['POST'];
require_once $_SERVER['DOCUMENT_ROOT'] . '/../app/ApiControl.php';

use Bin\SystemMethod;

$action = sanitizeString($_POST['action'] ?? '');

switch ($action) {
    case 'create':
        jsonResponse(['status' => 'success', 'message' => 'Oluşturuldu.'], 200);
        break;
    case 'update':
        jsonResponse(['status' => 'success', 'message' => 'Güncellendi.'], 200);
        break;
    case 'delete':
        jsonResponse(['status' => 'success', 'message' => 'Silindi.'], 200);
        break;
    default:
        jsonResponse(['status' => 'error', 'message' => 'Geçersiz action.'], 400);
}

PHPMailer (Mail)

📌 Configuración automática de .env: Cuando ejecuta el comando add phpmailer, la configuración SMTP se agrega automáticamente a su archivo .env y se crea la clase src/Service/Mailer.php.

Una clase contenedora (Wrapper) mucho más moderna, fluida y segura que funciona sobre la biblioteca PHPMailer. Todos los métodos de la clase se pueden encadenar (chainable).

Métodos y uso

  • ->to('mail@adres.com', 'İsim') : Establece a quién se enviará el correo electrónico.
  • ->cc('mail@adres.com') : Agrega destinatarios de copia de carbón (CC).
  • ->bcc('mail@adres.com') : Agrega destinatarios de copia oculta (BCC). Los destinatarios principales no pueden ver estas direcciones.
  • ->subject('Konu') : Establece el asunto (título) del correo electrónico.
  • ->attach('/path/fatura.pdf', 'Isim.pdf') : Agrega un archivo físico del servidor (o temporal) como archivo adjunto en el correo.
  • ->embedImage('/path/logo.png', 'logo_cid') : Incrusta una imagen en el correo electrónico para ser utilizada en HTML (<img src="cid:logo_cid">).
  • ->html('HTML Kodu') : Establece el contenido HTML. Crea automáticamente una versión de texto sin formato (AltBody).
  • ->text('Düz Metin') : Se usa si desea enviar el correo electrónico estrictamente como texto sin formato.
  • ->send() : Completa todas las operaciones encadenadas y envía el correo electrónico a través de SMTP. Lanza una Excepción si hay un error.

Ejemplo avanzado: Plantilla PHP (View) y archivo adjunto dinámico

Si no desea escribir el contenido HTML directamente en cadenas, puede usar ob_start() para incluir un archivo de plantilla PHP externo (que contenga variables) y adjuntar un PDF:

use App\Service\Mailer;

// 1. Tus datos dinámicos

// 2. Cargar plantilla HTML externamente (Output Buffering)
ob_start();
require_once $_SERVER['DOCUMENT_ROOT'] . '/views/email/siparis.php';
$htmlIcerik = ob_get_clean();

// 3. Enviar el correo
Mailer::create()
    ->to('musteri@mail.com', 'Ahmet Yılmaz')
    ->bcc('arsiv@sirket.com') // El cliente no puede ver esto
    ->subject('Siparişiniz Onaylandı: ' . $siparisNo)
    ->html($htmlIcerik)
    ->attach($pdfDosyasi, 'Siparis_Faturasi.pdf')
    ->send();
