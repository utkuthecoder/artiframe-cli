ArtiFrame Documentation

Framework for scalable native PHP projects managed with zero external dependencies, strict rules and a powerful CLI. No dependencies, a lightweight and fast ecosystem free from composer package soup, allowing you to focus on your business logic.

Introduction & Philosophy

ArtiFrame, "Convention over Configuration" It is based on the principle of (Rules Before Configuration). The power of a framework comes not from the richness of the tools it offers, but from the consistency of the order it establishes.

Zero Overhead

Zero dependencies on third-party Composer packages or libraries. Composer is used only to run the project's own PSR-4 autoloading mechanism. Every line of code is yours; free from unnecessary layers of abstraction.

Safety Comes First

XSS protection, CSRF validation, sanitization against SQL injection, and HTTP method checking are built-in by default. Security is not an option, it is a standard.

Strict Rule Set

A junior developer who just joined the project, data-js Understands the architecture and directory structure in minutes. Team compatibility is guaranteed at the framework level.

CLI Priority

There is no need to create view, API, class files manually. The CLI generates stub files, links assets, and keeps the project consistent.

💡 Addiction Philosophy: When creating a new project, world-standard composer packages such as phpmailer, redis, ramsey/uuid come installed. However, the ArtiFrame core does not depend on them. You can delete it whenever you want, download your own packages, and rewrite your functions according to your own architecture. ArtiFrame preserves your architectural freedom while reducing external dependency to zero.

Bootstrapper Architecture Kritik

ArtiFrame uses two completely independent bootstrappers. This architecture HTML header problems and security vulnerabilities radically prevents it.

View ViewControl.php

It is used for HTML pages (view files). Session starts, ViewMethod'u yükler.

// public/profile.php — TO THE TOP, before printing HTML
<?php
require_once $_SERVER['DOCUMENT_ROOT']
    . '/../app/ViewControl.php';
use Bin\ViewMethod;
?>
<!DOCTYPE html>
...

API ApiControl.php

Used for API endpoint files. Sets JSON header, performs HTTP method control, SystemMethodInstalls .

// public/api/user/getir.php
<?php
// $allowedMethods MUST be defined before require
$allowedMethods = ['GET'];

require_once $_SERVER['DOCUMENT_ROOT']
    . '/../app/ApiControl.php';

use Bin\SystemMethod;
🚫 ViewControl and ApiControl are never mixed: If ViewControl is required to an API file, HTML header may be returned instead of JSON header and the entire API response will be corrupted. If ApiControl is required on an HTML page, the session will not start and the page will break.

Rule Set Standart

Rule 1: data-js Architecture Kritik

JavaScript events are never class or id cannot be listened to over it. These are visual/style identities. All JS interactions data-js It is managed by the attribute. JavaScript never crashes when CSS deletes a class.

<!-- ❌ Anti-Pattern — not supported -->
<button id="submitBtn" class="btn">Gönder</button>
// JS: document.getElementById('submitBtn').addEventListener(...)

<!-- ✅ ArtiFrame Standard -->
<button class="btn btn-primary" data-js="login-submit">Gönder</button>
// JS: document.querySelector('[data-js="login-submit"]').addEventListener(...)

Rule 2: Theme Architecture

Dark/Light mode and themes, <html> of the label data-theme And data-mode It is managed through its attributes. Body classes are not used.

<!-- HTML opening tag from view.stub template -->
<html lang="tr" data-theme="default" data-mode="light">

/* theme definition in app.css */
html[data-theme="default"][data-mode="dark"] {
    --bg-color: #0b0c0e;
    --text-main: #ffffff;
}
html[data-theme="default"][data-mode="light"] {
    --bg-color: #ffffff;
    --text-main: #111111;
}

Rule 3: Secure Data Flow

Every data coming from the database is processed before being pushed to the DOM. display() It is wrapped with. Every data coming to the API is processed before it is processed. sanitizeString() or sanitizeInt() It is cleaned with .

Rule 4: Error Handling with APP_ENV

.env in the file APP_ENV The value determines error visibility. In Production, no error message is shown to the user.

//config/app-version.php
define('APP_ENV', (int)$_ENV['APP_ENV']); // 1=Debug, 0=Production

if (APP_ENV === 1) {
    ini_set('display_errors', 1);
    error_reporting(E_ALL);
} else {
    ini_set('display_errors', 0);
}

make:api CLI Komutu

It creates an API endpoint file by choosing one of two different templates. With every new API file $allowedMethods variable and ApiControl.php It comes with require ready.

standart — Single Action API

For endpoints that do a single job (login, send, delete). Business logic is written directly.

artiframe> make:api standard api/auth/login.php
<?php
$allowedMethods = ['POST']; // Accept POST only
require_once $_SERVER['DOCUMENT_ROOT'] . '/../app/ApiControl.php';

use Bin\SystemMethod;

//Business logic here...
jsonResponse(['status' => 'success'], 200);

switch-case — Multi-Action API

A structure that manages CRUD operations for a module in a single endpoint. action The parameter determines which operation will be performed.

artiframe> make:api switch-case api/user/admin.php
<?php
$allowedMethods = ['POST'];
require_once $_SERVER['DOCUMENT_ROOT'] . '/../app/ApiControl.php';

use Bin\SystemMethod;

$action = sanitizeString($_POST['action'] ?? '');

switch ($action) {
    case 'create':
        jsonResponse(['status' => 'success', 'message' => 'Created.'], 200);
        break;
    case 'update':
        jsonResponse(['status' => 'success', 'message' => 'Updated.'], 200);
        break;
    case 'delete':
        jsonResponse(['status' => 'success', 'message' => 'Deleted.'], 200);
        break;
    default:
        jsonResponse(['status' => 'error', 'message' => 'Invalid action.'], 400);
}

QR Code

📌 Wrapper Class: When you run the add qrcode command, the endroid/qr-code library is installed and the src/Service/QrCode.php wrapper class is created.

A modern and fluent class that hides the complex object instantiation (Builder/Writer) processes of the Endroid QR Code library, allowing you to generate a QR code and embed a logo in a single line.

Methods and Usage

  • ->generate('Metin') : Starts the chain by setting the text or URL to be converted to a QR code.
  • ->size(300) : Sets the width/height of the QR code in pixels (e.g. 300).
  • ->margin(10) : Sets the white margin around the QR code.
  • ->color('#000000', '#ffffff') : Sets the foreground (lines) and background colors as HEX codes (e.g. #000000, #ffffff).
  • ->logo('/path/logo.png', 50, true) : Embeds an image (logo) right in the center of the QR code. Takes the physical path, size, and whether to punch out the background.
  • ->format('png') : Sets the output format. png or svg are supported. Default: png.
  • ->save('/path/save.png') : Saves the generated QR code to a physical file on the server.
  • ->base64() : Returns the QR code as a base64 string so you can use it directly in an HTML <img src="..."> tag.
  • ->output() : Outputs the QR code directly to the browser with the appropriate HTTP headers.

Usage Examples

use App\Service\QrCode;

// Örnek 1: Ekrana HTML Img olarak basma
$base64 = QrCode::generate('https://artiframe.dev')
    ->size(400)
    ->logo($_SERVER['DOCUMENT_ROOT'] . '/assets/logo.png')
    ->base64();

echo '<img src="' . $base64 . '" alt="QR">';

// Örnek 2: Fiziksel PNG Olarak Kaydetme
QrCode::generate('VCARD Bilgileri')
    ->color('#ff0000', '#ffffff')
    ->save('/temp/kullanici_karti.png');

// Örnek 3: API Endpoint olarak resmi tarayıcıya basma
QrCode::generate('https://artilingo.com')->output();

PHPMailer (Mail)

📌 Automatic .env Setup: When you run the add phpmailer command, SMTP settings are automatically added to your .env file and the src/Service/Mailer.php class is created.

A much more modern, fluent, and secure (CRLF protected) Wrapper class working on top of the PHPMailer library. All methods provided by the class are chainable.

Methods and Usage

  • ->to('mail@adres.com', 'İsim') : Sets who the email will be sent to.
  • ->cc('mail@adres.com') : Adds Carbon Copy recipients.
  • ->bcc('mail@adres.com') : Adds Blind Carbon Copy recipients. Primary recipients cannot see these addresses.
  • ->subject('Konu') : Sets the subject (title) of the email.
  • ->attach('/path/fatura.pdf', 'Isim.pdf') : Adds a physical file from the server (or temp) as an attachment into the email.
  • ->embedImage('/path/logo.png', 'logo_cid') : Embeds an image into the email to be used in HTML (<img src="cid:logo_cid">).
  • ->html('HTML Kodu') : Sets the HTML content of the email. Automatically creates a plain text (AltBody) version for security.
  • ->text('Düz Metin') : Used if you want to send the email strictly as plain text.
  • ->send() : Completes all chained operations and sends the email via SMTP. Throws an Exception if there is an error.

Advanced Example: PHP Template (View) and Dynamic File Attachment

If you do not want to write the HTML content of the email directly in strings like spaghetti code, you can use ob_start() to include an external PHP template file (containing variables) and attach a dynamically generated PDF directly to the email:

use App\Service\Mailer;

// 1. Your dynamic data
$siparisNo = '#90210';
$pdfDosyasi = $_SERVER['DOCUMENT_ROOT'] . '/temp/fatura_90210.pdf';

// 2. Loading HTML Template externally (Output Buffering)
ob_start();
require_once $_SERVER['DOCUMENT_ROOT'] . '/views/email/siparis.php';
$htmlIcerik = ob_get_clean();

// 3. Sending the Mail
Mailer::create()
    ->to('musteri@mail.com', 'Ahmet Yılmaz')
    ->bcc('arsiv@sirket.com') // Customer cannot see this
    ->subject('Siparişiniz Onaylandı: ' . $siparisNo)
    ->html($htmlIcerik)
    ->attach($pdfDosyasi, 'Siparis_Faturasi.pdf')
    ->send();
