ArtiFrame Documentation

A scalable native PHP project framework with zero external dependencies, strict rules, and managed by a powerful CLI. No dependencies, free from composer package soup, allowing you to focus on your business logic in a lightweight and fast ecosystem.

Introduction & Philosophy

ArtiFrame is based on the "Convention over Configuration" principle. The power of a framework comes not from the richness of the tools it offers, but from the consistency of the order it establishes.

Zero Overhead

Zero dependency on third party Composer packages or libraries. Composer is only used to run the project's own PSR-4 autoloading mechanism. Every line of code is yours; free from unnecessary abstraction layers.

Security Comes First

XSS protection, CSRF validation, sanitization against SQL injection, and HTTP method checking are built-in by default. Security is not an option, it's a standard.

Strict Rule Set

A junior developer joining the project will grasp the data-js architecture and directory structure in minutes. Team harmony is guaranteed at the framework level.

CLI First

No manual creation of View, API, or class files. CLI generates them from stub files, sets up asset connections, and keeps the project consistent.

ℹ️ AGPLv3 License: ArtiFrame is open source. Derivative works you produce can be used freely provided the source code remains open. The copyright notice cannot be removed.

Installation

ArtiFrame CLI is installed as a global PHP tool. Installed once, used in every project.

1. Install CLI Tool Globally

# Global installation via NPM
npm install -g @artilingo/artiframe-cli

# Verify installation
artiframe

2. Interactive Shell

Just type artiframe in the terminal and press Enter. The CLI does not close; an interactive shell opens constantly listening for commands:

==================================================
        ArtiFrame CLI Interactive Shell v1.0.0
==================================================
Type 'help' for commands, or 'exit' to quit.

artiframe>

3. Start a New Project

artiframe> new my-project

This command creates the my-project/ directory and copies the entire skeletal structure into it: app/, bin/, config/, public/, src/, .env.example, and the first index.php page.

While the project is being created, the CLI will interactively ask you for the project's name (package), description, author information, type, and open source license, and injects this information into the new project's composer.json file.

When the process is complete, a new terminal window will automatically open in the project directory, and the artiframe CLI will start ready in that project!

4. Environment Settings

cp .env.example .env

Open your .env file and fill in the database and application details. This file should never be committed to version control.

⚠️ Web Server Setup: Point the document root of Apache/Nginx to the /public/ folder. Other directories should never be accessible from the outside.

Directory Structure

The architecture created when the project starts ensures a clear separation of concerns (SoC).

project-name/ ├── app/ # Infrastructure layer │ ├── ViewControl.php # View (HTML page) bootstrapper │ ├── ApiControl.php # API endpoint bootstrapper │ ├── Database.php # PDO based database connection │ ├── DotEnv.php # .env reader │ └── R2Manager.php # Cloudflare R2 file manager │ ├── bin/ # ⚠️ Core system — do not edit directly │ ├── SystemMethod.php # API/Backend global helpers │ ├── ViewMethod.php # View/Frontend global helpers │ └── stubs/ # Template files used by CLI │ ├── view.stub │ ├── api-standart.stub │ ├── api-switch-case.stub │ └── class.stub │ ├── config/ # Configuration files │ └── app-version.php # APP_VERSION and APP_ENV constants │ ├── public/ # ← The only accessible directory for the web server │ ├── assets/ │ │ ├── css/ # View specific CSS files │ │ └── js/ # View specific JS files │ ├── includes/ # Shared components │ │ ├── head.php │ │ ├── header.php │ │ └── footer.php │ ├── api/ # API endpoint files │ └── index.php # Home page │ ├── src/ # Business logic and classes ├── .env # Environment variables (not in git) ├── .env.example # Template — committed to git └── kilavuz.html # This document
🚫 Do not touch the bin/ directory: The files inside bin/ are the core of the framework. Project-specific business logic is not added here. Classes and services you add should be placed under src/, and infrastructure components under app/.

Bootstrapper Architecture Critical

ArtiFrame uses two completely independent bootstrappers. This architecture fundamentally prevents HTML header issues and security vulnerabilities.

View ViewControl.php

Used for HTML pages (view files). Starts session, loads ViewMethod.

// public/profile.php — AT THE VERY TOP, before printing HTML
<?php
require_once $_SERVER['DOCUMENT_ROOT']
    . '/../app/ViewControl.php';
use Bin\ViewMethod;
?>
<!DOCTYPE html>
...

API ApiControl.php

Used for API endpoint files. Sets the JSON header, performs HTTP method checking, loads SystemMethod.

// public/api/user/get.php
<?php
// $allowedMethods MUST be defined before require
$allowedMethods = ['GET'];

require_once $_SERVER['DOCUMENT_ROOT']
    . '/../app/ApiControl.php';

use Bin\SystemMethod;
🚫 ViewControl and ApiControl are never mixed: If ViewControl is required in an API file, an HTML header might be returned instead of a JSON header, breaking the entire API response. If ApiControl is required on an HTML page, the session won't start and the page will break.

Rule Set Standard

Rule 1: data-js Architecture Critical

JavaScript events can never be listened to via a class or id. These are visual/style identifiers. All JS interactions are managed using the data-js attribute. JavaScript will never crash when CSS deletes a class.

<!-- ❌ Anti-Pattern — unsupported -->
<button id="submitBtn" class="btn">Submit</button>
// JS: document.getElementById('submitBtn').addEventListener(...)

<!-- ✅ ArtiFrame Standard -->
<button class="btn btn-primary" data-js="login-submit">Submit</button>
// JS: document.querySelector('[data-js="login-submit"]').addEventListener(...)

Rule 2: Theme Architecture

Dark/Light mode and themes are managed via the data-theme and data-mode attributes on the <html> tag. Body classes are not used.

<!-- HTML opening tag from view.stub template -->
<html lang="en" data-theme="default" data-mode="light">

/* Theme definition in app.css */
html[data-theme="default"][data-mode="dark"] {
    --bg-color: #0b0c0e;
    --text-main: #ffffff;
}
html[data-theme="default"][data-mode="light"] {
    --bg-color: #ffffff;
    --text-main: #111111;
}

Rule 3: Secure Data Flow

Every piece of data coming from the database is wrapped with display() before being output to the DOM. Every piece of data coming into the API is cleaned with sanitizeString() or sanitizeInt() before being processed.

Rule 4: Error Management with APP_ENV

The APP_ENV value in the .env file determines error visibility. In production, error messages are not shown to the user.

// config/app-version.php
define('APP_ENV', (int)$_ENV['APP_ENV']); // 1=Debug, 0=Production

if (APP_ENV === 1) {
    ini_set('display_errors', 1);
    error_reporting(E_ALL);
} else {
    ini_set('display_errors', 0);
}

CLI Ecosystem

The ArtiFrame CLI opens an interactive shell when artiframe is typed in the terminal. All commands run within this shell. Commands can also be run once.

# Interactive mode (recommended)
artiframe
artiframe> make:view admin/users.php

# Single run mode
artiframe make:view admin/users.php

new CLI Command

Creates a new ArtiFrame project. Generates the entire directory skeleton, bootstrapper files, and the initial index page.

artiframe> new project-name

Interactive Process: When the command is executed, it will ask you questions for the project's composer.json metadata (Package Name, Description, Author, Type, License). All licensing and details are determined at this stage.

Auto Terminal: Once the project is successfully created, a brand new terminal window positioned in the project directory with artiframe started is automatically opened, according to your OS.

Generated structure:

project-name/ ├── app/ (ViewControl.php, ApiControl.php, Database.php, DotEnv.php) ├── bin/ (SystemMethod.php, ViewMethod.php, stubs/) ├── config/ (app-version.php) ├── public/ (index.php, assets/, includes/, api/) ├── src/ ├── .env.example └── kilavuz.html

make:view CLI Command

Generates a new page (view) file and its specific CSS/JS assets. Assets are automatically linked to the page and cache-busting is applied using ?v=APP_VERSION.

artiframe> make:view admin/users.php

Generated files:

✔  public/admin/users.php
✔  public/assets/css/admin/users.css
✔  public/assets/js/admin/users.js

The generated view file comes with ViewControl required at the top, head/header/footer includes added, and CSS/JS links connected with cache-busting.

make:api CLI Command

Generates an API endpoint file by choosing one of two different templates. Each new API file comes with the $allowedMethods variable and ApiControl.php requirement ready.

standart — Single Action API

For endpoints that do a single job (login, submit, delete). Business logic is written directly.

artiframe> make:api standart api/auth/login.php
<?php
$allowedMethods = ['POST']; // Only accept POST
require_once $_SERVER['DOCUMENT_ROOT'] . '/../app/ApiControl.php';

use Bin\SystemMethod;

// Business logic goes here...
jsonResponse(['status' => 'success'], 200);

switch-case — Multi Action API

A structure that manages CRUD operations for a module in a single endpoint. The action to be taken is determined by the action parameter.

artiframe> make:api switch-case api/user/manage.php
<?php
$allowedMethods = ['POST'];
require_once $_SERVER['DOCUMENT_ROOT'] . '/../app/ApiControl.php';

use Bin\SystemMethod;

$action = sanitizeString($_POST['action'] ?? '');

switch ($action) {
    case 'create':
        jsonResponse(['status' => 'success', 'message' => 'Created.'], 200);
        break;
    case 'update':
        jsonResponse(['status' => 'success', 'message' => 'Updated.'], 200);
        break;
    case 'delete':
        jsonResponse(['status' => 'success', 'message' => 'Deleted.'], 200);
        break;
    default:
        jsonResponse(['status' => 'error', 'message' => 'Invalid action.'], 400);
}

make:class CLI Command

Generates a new PHP class file with namespace and class boilerplate ready. The namespace is determined automatically based on the class path. If a directory other than app/ and src/ (e.g. private/) is used, the CLI tool automatically runs the composer dump-autoload script in the background.

artiframe> make:class src/Service/EmailService.php

If the class directory is not specified, the command returns an error:

artiframe> make:class
❌ Error: The directory where the class will be created must be specified! (e.g. /app or /src)
Example: /src/Service/PaymentService

Updates the version number in config/app-version.php according to semantic versioning (SemVer) rules. Version format: MAJOR.MINOR.PATCH

View Helpers — display() ViewMethod

Applies mandatory XSS protection when outputting data from the database or user input to the DOM. Returns a default value instead of throwing an error for null or empty values.

string display(mixed $data, string $default = '')
💡 Tip: Using $default
The second parameter ($default) is a fallback text that will be printed to the screen if the data coming from the database is empty (null, false, empty string). For example, if you use display($name, 'Anonymous') for a user whose name data is not entered, your page will present meaningful content instead of ugly blanks. 
<!-- ❌ Insecure — creates an XSS vulnerability -->
<h1><?= $user['name'] ?></h1>

<!-- ✅ ArtiFrame Secure Usage -->
<h1><?= display($user['name'], 'Anonymous User') ?></h1>

View Helpers — escapeUrl() ViewMethod

Used when printing links received from users (e.g. profile websites) into <a href="..."> or <img src="..."> tags. Neutralizes dangerous payloads like javascript:alert(1) (Stored XSS), preventing code execution via links.

string escapeUrl(string $url) 
<!-- ❌ Insecure — JS code can be leaked via URL -->
<a href="<?= $user['website'] ?>">Visit Site</a>

<!-- ✅ ArtiFrame Secure Usage -->
<a href="<?= escapeUrl($user['website']) ?>">Visit Site</a>

View Helpers — csrfField() ViewMethod

Adds a hidden token field to HTML forms to protect against CSRF attacks. Mandatory for every page containing a POST form.

string csrfField() 
<form action="/api/save.php" method="POST">
    <?= csrfField() ?>   <!-- Mandatory for security -->
    <input type="text" name="name">
    <button type="submit" data-js="save-btn">Save</button>
</form>

View Helpers — String Operations ViewMethod

slugify(...$texts)

string slugify(string ...$texts)

Takes an unlimited number of texts or variables and converts them into an SEO-friendly URL format by putting hyphens (-) between them. Note: This function works universally in both ViewMethod (frontend) and SystemMethod (backend)!

System Helpers — apiResponse() SystemMethod

ArtiFrame's standard and universal JSON output generator. It must be used when sending data from APIs to JavaScript. It standardizes the development process by always sending a consistent (status, message, data) object to the JS (Frontend) developer.

void apiResponse(string $status, string $message, array $data = [], \Throwable $exception = null)
💡 Smart Error Handling (APP_ENV Support)
If you pass an $e (Exception) to the 4th parameter; when in APP_ENV = 1 (Debug) mode, the actual PHP error, line, and file path are printed instead of the user-written message. But when the server is set to APP_ENV = 0 (Prod) mode, the system automatically hides Exception logs and only returns your clean "An error occurred" message. 
// Successful response
apiResponse('success', 'User saved.', ['id' => $newId]);

// Smart error handling with Try-Catch
try {
    // Database operations...
} catch (\Exception $e) {
    // In Prod mode: "A problem occurred during registration."
    // In Debug mode: "SQL Error: duplicate key... (File: user.php Line: 45)"
    apiResponse('error', 'A problem occurred during registration.', [], $e);
}

System Helpers — jsonResponse() SystemMethod

Sets the JSON header, provides the HTTP status code, and prints the output with json_encode. (Usually not used directly, apiResponse() should be preferred instead.)

void jsonResponse(array $data, int $statusCode = 200) 
// Old style / Custom formatted response
jsonResponse(['operation_result' => 'ok'], 200);

System Helpers — verifyCsrf() SystemMethod

Verifies that the incoming POST request comes from a legitimate form. Returns false if csrfField() is not included in the form or if the token is invalid.

bool verifyCsrf(string $token) 
if (!verifyCsrf($_POST['csrf_token'] ?? '')) {
    jsonResponse(['status' => 'error', 'message' => 'Invalid CSRF token.'], 403);
}

API — HTTP Method Check ApiControl

The $allowedMethods array must be defined before requiring ApiControl. By reading this array, ApiControl automatically rejects requests from disallowed methods with 405 Method Not Allowed.

// An endpoint that only accepts GET and POST
$allowedMethods = ['GET', 'POST'];
require_once ... . '/../app/ApiControl.php';

// An endpoint that only accepts DELETE
$allowedMethods = ['DELETE'];
require_once ... . '/../app/ApiControl.php';

Preflight OPTIONS requests automatically return 200 for CORS and the script terminates — no manual intervention needed.

API — CORS ApiControl (Commented)

If you want to allow API access from other domains or mobile applications, activate the CORS block inside ApiControl.php.

// Inside ApiControl.php — activated by removing comments
header("Access-Control-Allow-Origin: https://your-domain.com");
header("Access-Control-Allow-Methods: GET, POST, OPTIONS");
header("Access-Control-Allow-Headers: Content-Type, Authorization");
⚠️ Do not use * (all domains) in Production environment. Explicitly specify the domain address.

API — Rate Limiting ApiControl (Commented)

To prevent malicious users or bots from flooding the API, you can activate the Rate Limiting block in ApiControl.php. Default rule: 60 requests per 60 seconds / IP.

⚠️ Redis Server Required: The Rate Limiting feature works using Redis via the \Src\Service\RedisService::getInstance() class. Before opening this block of code, make sure you have installed a Redis service in your project and created a connection class under src/Service/. 
// If more than 60 requests come from the same IP in 60 seconds:
http_response_code(429); // Too Many Requests
echo json_encode(['error' => 'Too many requests. Please wait.']);

Full Workflow: Contact Form (End-to-End)

Let's examine step by step how to develop a Contact Form feature from scratch following ArtiFrame standards.

  1. Create the View File 
    artiframe> make:view contact.php
✔  public/contact.php
✔  public/assets/css/contact.css
✔  public/assets/js/contact.js
  2. Create API Endpoint 
    artiframe> make:api standart api/contact/submit.php
  3. Code the HTML Form
    Add the following form to the public/contact.php file: 
    <form action="/api/contact/submit.php" method="POST">
    <?= csrfField() ?>
    <input type="text"  name="name"      placeholder="Your Name">
    <input type="email" name="email"     placeholder="Email">
    <textarea name="message" placeholder="Your Message"></textarea>
    <button type="submit" data-js="contact-submit">Send</button>
</form>
  4. Connect Fetch API with JavaScript
    In the public/assets/js/contact.js file: 
    document.querySelector('[data-js="contact-submit"]').addEventListener('click', async (e) => {
    e.preventDefault();
    const formData = new FormData(e.target.closest('form'));
    const res = await fetch('/api/contact/submit.php', {
        method: 'POST',
        body: formData
    });
    const data = await res.json();
    console.log(data);
});
  5. Complete Server Logic (Backend)
    In the public/api/contact/submit.php file: 
    <?php
$allowedMethods = ['POST'];
require_once $_SERVER['DOCUMENT_ROOT'] . '/../app/ApiControl.php';
use Bin\SystemMethod;

// 1. CSRF Validation
if (!verifyCsrf($_POST['csrf_token'] ?? '')) {
    jsonResponse(['error' => 'Invalid token.'], 403);
}

// 2. Sanitize Data
$name    = sanitizeString($_POST['name'] ?? '');
$email   = sanitizeEmail($_POST['email'] ?? '');
$message = sanitizeString($_POST['message'] ?? '');

// 3. Business Logic (Send email, save to DB, etc.)
// ...

// 4. Respond
jsonResponse(['status' => 'success', 'message' => 'Your message has been received.'], 200);
✅ Completed! You have created a fully secure and standard-compliant form flow with XSS protection, CSRF validation, HTTP method restriction, and data-js architecture.
