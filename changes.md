# ArtiFrame CLI Changes Log

## [v2.0.0] - Unreleased

### Added
- **Global Helper Functions:** Helper functions inside `SystemMethod` and `ViewMethod` are now wrapped in a global `namespace { }` block with `function_exists` checks. Developers can now use `display()`, `csrfField()`, `routeLink()` etc. directly anywhere without importing namespaces.
- **File-based Routing Engine:** Introduced a new `routeLink()` method in `ViewMethod.php`. This engine automatically parses the URL, finds the longest matching `.php` file in the document root, and maps the remaining segments into `$_GET['params']` and `$_GET['param1']`, `$_GET['param2']` for seamless, zero-config routing.
- **Default 404 & 503 Pages:** Added automatic generation of basic `404.php` and `503.php` templates during `artiframe new` to support the new routing engine's error handling and maintenance modes.
- **Upgrade Command:** Introduced `artiframe upgrade` to safely update core files while preserving existing user logic and custom code.

### Changed (BREAKING CHANGES)
- **`public/index.php` Architecture:** The `index.php` file no longer serves as the welcome HTML page. It has been stripped down to act exclusively as the main router utilizing `routeLink()`.
- **Welcome Page Renamed:** The default welcome HTML page generated by `artiframe new` has been renamed to `public/landing.php`. 
- **Backwards Compatibility:** Existing projects upgrading to v2.0.0 will need to rename their custom `index.php` pages or adopt the `routeLink()` routing pattern, as `index.php` is now strictly reserved for the routing engine.
